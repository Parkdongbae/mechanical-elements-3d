배우는 기계요소(화면의 `기계요소로 보면` 카드에 쓴다):
| 물레방아 부품 | 기계요소로 보면 | 이 앱의 관련 부품 |
|---|---|---|
| 굴통(굴대) | 바퀴와 함께 돌며 힘을 전하는 **축** | 전동축 |
| 굴통을 받치는 받침 기둥의 홈 | 도는 축을 받쳐 주는 곳 — **베어링과 같은 역할**(구슬 없이 나무 홈이 직접 받친다) | 볼 베어링 |

| 방아채 + 볼씨 | 캠을 따라 움직이는 부분(캠 폴로어)이자 **지레**(받침점 = 볼씨) | 캠, 링크 |

### 0-1. 참고 자료에서 확인한 것 (이 표 밖의 사실·연도·수치는 화면에 쓰지 않는다)

참고 글: kh.or.kr 게시 글 「현대 동력 장치의 뿌리이자 친환경적인 에너지원 '방아'」(윤용현, 2014.6. 게시). 방아 전반(절구·디딜방아·맷돌·연자매·물레방아)을 다루며 물레방아는 한 단락 + 그림 1장이다.
**글·사진·그림은 복제하지 않는다. 형태와 명칭만 참고하고 문장은 새로 쓴다.**

| 구분 | 자료 내용 | 이 실험에서 |
|---|---|---|
| 그림 「물레방아 세부명칭」의 부품 이름 | **물홈, 물레바퀴, 날개, 굴통(굴대), 누름대(발), 방아채, 방아공이, 확돌** | 이름표·화면 문구는 이 이름을 그대로 쓴다 |
| 그림의 형태 | 물홈의 물이 바퀴 **위쪽**으로 떨어짐. 바퀴 옆으로 긴 굴통이 나오고, 굴통을 가로지르는 누름대가 방아채 꼬리를 누름. 방아채 끝에 공이, 그 아래 확돌. 방아채가 2개로 보임 | 위에서 물을 받는 바퀴 + 방아채 2개로 만든다(2개인 것은 그림 해석 — 모형 결정) |
| 본문의 용어 | 캠 역할 = `방아눌림목`, 캠 폴로어 = `방아다리` | 본문과 그림의 이름이 다르다. 화면은 그림 이름(누름대·방아채)으로 통일. `방아눌림목`은 `더 알아보기`에 "누름대를 방아눌림목이라고도 한다"로만. **`방아다리 = 방아채`인지는 자료만으로 확정 못 함 → 화면에 `방아다리`는 쓰지 않는다** |
| 디딜방아 단락 | 지레의 원리. 힘점 = 다리, 받침점 = **볼씨**, 작용점 = **방앗공이** | 받침점 이름표를 `볼씨(받침점)`로. 공이 표기는 그림의 `방아공이`로 통일 |
| 치수 | 물레바퀴 지름 220~489 cm, 폭 75~115 cm. 표준형 지름 330 cm, 폭 100 cm | 모형 = 표준형(지름 3.30 m, 폭 1.00 m) |
| 날개 | 32개, 각도 25°, 길이 400 mm일 때 효율이 가장 높다고 분석 | 날개 32개, 길이 0.40 m, 25°(무엇에 대한 각도인지는 자료에 없음 → "반지름 방향에서 25° 기울임"은 모형 결정) |
| 물 | 물레바퀴까지 낙차 10~30 cm, 표준형 유량 초당 320 L | 낙차 0.20 m 고정, 기본 물의 양 320 L/s |
| 빠르기·힘 | 1분에 18~25회 회전, 8~10마력, 벼 한 가마니 찧는 데 25~40분 | 기본 상태에서 21.5회/분이 나오게 모형을 맞춘다(5절). 마력·찧는 시간은 `자료에 나온 값` 카드에만 |
| 원리 | 물의 위치 에너지 → 운동 에너지, 회전 운동 → 왕복(상하) 운동, 캠 | 단계 설명의 뼈대 |

자료에 **없어서 쓰지 않는 것 / 주의할 것**
- 굴통 굵기, 누름대 길이·개수, 방아채 길이, 공이 무게, 확돌 크기, 받침 기둥·수문 → 전부 **모형 치수**(4절). 화면 `자료에 나온 값` 카드에는 넣지 않는다.
- 지역별 종류, 물방아(통방아)와의 차이 설명, 상사식/하사식 같은 분류어 → 본문에 없음. 쓰지 않는다. (물방아 그림은 있지만 이 실험 범위 밖.)
- 본문의 "1870년대 증기 기관 발명" 문장은 **연대가 맞지 않으므로 인용하지 않는다.** 증기 기관·연도 언급 금지.
- 본문은 `8~10마력(10~13㎾)`라고 적었지만 두 값은 서로 맞지 않는다(8~10마력 ≈ 6~7 kW). **kW 환산값은 쓰지 않고 "8~10마력"만** 자료 값으로 적는다.
- 출처 표기 문구의 기관 이름은 Opus가 페이지 머리말에서 확인해 적는다(확인 못 하면 `kh.or.kr 게시 글`).

## 4. 공통 계약 — `src/labs/mill/types.ts` (Opus가 먼저 작성, 내용 고정)

```ts

export const G_ACC = 9.81;
export const RHO = 1000;

/** 치수(실제 m). ★ = 참고 자료의 표준형 값, 나머지는 모형 결정 */
export const MILL = {
  // 물레바퀴 (중심 x=0, y=AXIS_Y, z=0)
  wheelR: 1.65,        // ★ 지름 3.30
  wheelW: 1.0,         // ★ 폭
  blades: 32,          // ★
  bladeLen: 0.4,       // ★ 날개 길이(반지름 방향 깊이) → 칸 안쪽 반지름 1.25
  bladeTilt: 25,       // ★ 도. 반지름 방향에서 기울인 각(해석은 모형 결정)
  head: 0.2,           // ★ 물홈 끝에서 바퀴 꼭대기까지 낙차(자료 10~30 cm)
  qStd: 0.32,          // ★ 표준 유량 m³/s (320 L/s)
  qMax: 0.48,
  axisY: 1.0,          // 굴통 중심 높이(바퀴 아래쪽 0.65는 구덩이 속)
  pitDepth: 1.0,
  // 물이 실리는 구간(바퀴 꼭대기에서 잰 각)
  rMean: 1.45,         // 칸에 담긴 물의 평균 반지름
  phiIn: 10, phiOut: 150, // 도
  bucketCap: 0.0569,   // 한 칸에 담기는 최대 부피 m³ (= 1.0 × 0.4 × (2π·1.45/32) × 0.5)
  // 굴통·누름대
  shaftR: 0.2, shaftX0: -0.75, shaftX1: 3.3,
  armR: 0.6,           // 굴통 중심에서 누름대 끝까지
  armX: [1.7, 2.6] as const,          // 방아채 1·2의 x 위치
  armOffset: [0, 90] as const,        // 도. 방아채 i의 누름대 끝 각 = θ + armOffset[i], 그리고 +180°(막대가 굴통을 관통해 끝이 2개)
  // 방아채(지레)
  pivotZ: 1.3, pivotY: 0.7,           // 볼씨(받침 축)
  tailLen: 1.0,        // 받침 축 ~ 꼬리 끝(누름대가 닿는 길이 a)
  pestleArm: 1.8,      // 받침 축 ~ 공이 중심선(b)
  beamLen: 3.0,        // 꼬리 1.0 + 공이 쪽 2.0
```

### 5-2. 누름대(캠)와 방아채(지레) — 닫힌 식

방아채는 z축 방향으로 놓이고 볼씨 `P = (z 1.30, y 0.70)`을 중심으로 돈다. 꼬리는 굴통 쪽(−z), 공이는 +z 쪽.
**누름대가 닿는 꼬리 윗면은 받침 축 중심을 지나는 평면**으로 둔다(모형 결정 — B도 이 면에 맞춰 만든다).

- 누름대 끝 `C(φ) = (0.60 sin φ, 1.00 + 0.60 cos φ)`.
- 닿는 조건: `P.z − C.z > 0` 이고 `|C − P| ≤ tailLen(1.0)` 이고 `β ≥ βrest`.
- 그때 `β = atan2(P.y − C.y, P.z − C.z)` — 끝이 내려갈수록 꼬리가 눌려 β가 커진다(공이가 올라간다).
- 끝이 꼬리 끝(받침 축에서 1.0)을 벗어나는 순간 **빠진다** → 방아채는 볼씨를 중심으로 자유롭게 돈다.
- 공이 높이 `h = 1.8 × (sin β − sin(−3°))`.
- 방아채가 받는 중력 토크 `G·cos β`, `G = g × (공이 30 × 1.8 + 방아채 60 × 0.5) = 824.04 N·m`(방아채 무게중심은 받침 축에서 공이 쪽으로 0.5).
  관성 모멘트 `I = 30 × 1.8² + 60 × 3.0² / 12 + 60 × 0.5² = 157.2 kg·m²`(공이는 점 질량으로 — 단순화).
- 빠진 뒤: `β'' = −G cos β / I`. 빠지는 순간의 `β'`(위로 올라가던 속도)를 그대로 이어받는다 → **조금 더 떠올랐다가 떨어진다.** `β ≤ βrest`가 되면 그 자리에서 멈춘다(튀지 않음 — 곡식이 받아 줌). 그 순간의 `speed = −β' × 1.8`, `energy = ½ I β'²`, `fallTime`(빠진 때부터), `peakLift`를 `Strike`로 기록.
- 매 잘게 나눈 단계에서: 먼저 자유 운동으로 β를 구하고, 그 방아채의 누름대 끝 2개 중 `betaCam ≥ β`인 것이 있으면 **눌린 상태**(`β = betaCam`, `β' = dβcam/dθ × ω`). 떨어지는 중에 다음 누름대를 만나면 그 자리에서 받는다(같은 규칙으로 자연히 처리).
- 누름대가 방아채를 누르는 동안 굴통이 받는 반대 토크 `Tcam = G cos β × dβcam/dθ`(준정적 — 방아채를 가속하는 힘과 닿는 순간의 충격, 미끄럼 마찰은 무시. 화면 `이 실험의 약속`에 적는다).

검산값(이 지시서 작성 때 수치로 확인)
| 누름대 끝 각 φ | β | 공이 높이 h |
|---|---|---|
| 115.70° (닿기 시작, `CAM.on`) | −3.00° | 0.000 m |
| 120° | 0.00° | 0.094 m |
| 132° | 6.78° | 0.307 m |
| 144° | 11.07° | 0.440 m |
| 147.59° (빠짐, `CAM.off`) | 11.92° | **0.466 m** (`CAM.lift`) |

- 누르는 구간 = 31.9°. 한 번 들어 올리는 일 `CAM.liftEnergy = G × (sin 11.92° − sin(−3°)) = 213.3 J`. 누르는 동안 `Tcam` 최댓값 약 599 N·m(닿는 순간).
- 아주 천천히 돌릴 때(ω → 0): 떨어지는 시간 0.318 s, 닿는 빠르기 2.97 m/s, 찧는 에너지 213 J.
  비교용 — 같은 높이에서 그냥 떨어뜨리면 `√(2 × 9.81 × 0.466) = 3.02 m/s`, `√(2 × 0.466 / 9.81) = 0.308 s`. (방아채는 볼씨를 중심으로 돌면서 떨어져 조금 다르다 — 숫자판 basis에 이 비교를 적는다.)
- 21.5회/분으로 돌 때: 누르는 시간 0.247 s, 빠진 뒤 최고 높이 0.504 m, 떨어지는 시간 0.424 s, 닿는 빠르기 3.09 m/s, 찧는 에너지 231 J. 다음 누름대가 닿기까지 1.148 s(그 전에 다 떨어져 있다).
- 방아채 2의 누름대는 90° 어긋나 있어 두 방아채가 **번갈아** 찧는다. 굴통 한 바퀴에 공이 하나가 2번, 합쳐 4번. 두 방아채가 동시에 눌리는 순간은 없다.

### 5-3. 물 → 바퀴 빠르기 (이 실험의 모형 — 화면에 "모형"이라고 밝힌다)

- 물홈 끝에서 낙차 0.20 m: 바퀴에 닿는 빠르기 `√(2 × 9.81 × 0.20) = 1.98 m/s`(표시용).
- 물은 꼭대기에서 10° 지난 곳(φin)에서 칸에 담겨 150°(φout)에서 쏟아진다. 실린 구간 `Δφ = 140° = 2.4435 rad`, `Δc = cos 10° − cos 150° = 1.8508`.
- 바퀴에 실린 물 `M`: `dM/dt = ρ·flow − M·ω/Δφ`, `0 ≤ M ≤ ρ × bucketCap × 32 × Δφ/2π = 708.6 kg`(넘치면 버려진다).
- 물이 주는 토크 `Tw = M g rMean Δc / Δφ` — 실린 물의 무게가 한쪽으로 치우쳐 바퀴를 돌린다. 한결같이 돌 때 `M = ρQΔφ/ω`이므로 `Tw·ω = ρ g Q × (rMean Δc = 2.68 m)` = 물이 칸에 실려 내려가는 동안 내놓는 일률(`waterPower`).
- 운동 방정식 `(wheelInertia + M rMean²) × dω/dt = Tw − frictionT − dragC·ω − ΣTcam`. ω = 0일 때는 `Tw`가 `frictionT + ΣTcam`을 넘어야 움직이기 시작한다(물이 조금씩 차오르다가 돌기 시작). ω는 음수가 되지 않는다.
- 수문: 닫으면 `flow`가 0.8초에 걸쳐 0으로, 열면 `q`로. 닫으면 바퀴의 물이 빠지며 천천히 멈춘다.
- `steadyOmega(Q)`: `dragC·ω² + (frictionT + T̄cam)·ω − K·Q = 0`의 양의 해. `K = ρ g rMean Δc = 26 327`, `T̄cam = 4 × 213.3 / 2π = 135.8 N·m`.
- `dragC`는 물이 튀고 새는 손실·곡식을 찧는 저항 등을 한데 묶은 값으로, **표준 유량 320 L/s에서 자료의 범위(18~25회/분) 가운데인 21.5회/분이 나오도록 맞춘 것**이다. 실측값이 아니다.

검산값(`steadyOmega`; 시뮬레이션 20초 뒤 최근 한 바퀴 평균은 이 값의 ±3% 안)
| 물의 양 | 회전 | 공이 하나가 찧는 횟수 | 실린 물 | 물이 내놓는 일률 | 방아 2개가 쓰는 일률 |
|---|---|---|---|---|---|
| 50 L/s | 8.1회/분 | 16.2회/분 | 144 kg | 1.32 kW | 115 W |

| 240 L/s | 18.5회/분 | 37.1회/분 | 302 kg | 6.32 kW | 263 W |
| **320 L/s** | **21.5회/분** | **43.0회/분** | 347 kg | **8.42 kW** | 306 W |

`방아가 쓰는 일률 = 4 × 213.3 J × 회전수 ÷ 60`. 화면 문구: "이 모형에서는 물이 내놓는 일의 일부만 공이를 들어 올리는 데 쓰여요. 나머지는 마찰과 물 튐으로 사라져요."

### 6-3. 물(`water.ts`)

- **물홈 속 흐름**: 반투명 파란 볼륨(`glass(0x2f86e6, 0.62)` — `pump/model.ts`와 같은 물색). 깊이는 `flow`에 비례(0~0.18). 흐르는 방향이 보이게 물 위에 밝은 줄무늬 조각 몇 개가 +z로 이동(빠르기 일정).
- **떨어지는 물줄기**: 물홈 끝 → 바퀴 꼭대기 근처 칸. 폭 0.6의 얇은 곡면 + 물방울.
- **칸 속 물**: φin~φout 사이 칸마다 물 덩어리. 칸 하나의 양 = `waterMass ÷ (32 × Δφ/2π ≈ 12.4칸)`, 채움 비율 = 그 부피 ÷ `bucketCap`(320 L/s에서 약 49%). **물의 윗면은 항상 수평**(칸이 돌아도 물은 기울지 않는다). φout 30° 전부터 줄어들며 쏟아지는 것으로 그린다(그림만의 단순화 — 계산은 φout에서 한 번에).
- **쏟아지는 물·물방울**: `InstancedMesh` 입자 400개 이하, 중력으로 떨어져 구덩이 물에 닿으면 사라짐. `flow = 0`이면 새 입자 없음.
- **구덩이 물**: 얕은 물이 +z로 흐름(줄무늬 이동).
- 물 관련 메시는 `castShadow = false`. 60fps 유지. `userData.noAO = true`가 필요한 반투명 메시는 표시.

## 7. 이름표 (모든 부품, 켜고 끄기)

## 8. 19-C 화면·통합

### 8-1. 구조와 단계

- `WaterMill.ts`: `AppMode`. `enter`에서 모델·계산·패널 생성, 리스너 등록. `exit`에서 **전부** 정리(DOM, `sceneMgr.remove`, `model.dispose()`, 리스너, `controls` 상태 복원, `camera.clearViewOffset()`, `window.__wm` 삭제). enter/exit 20회에 누수 없음.
- 매 프레임: `physics.step(dt)` → `model.apply(state)` → `model.updateWater(state, dt)` → 찧은 기록마다 `model.strike` + (소리 설정이 켜져 있으면 `ctx.playSound`는 쓰지 않는다 — 정답/오답용이다. 소리 없음) → 0.1초마다 숫자판, 이름표 위치 갱신.
- 좌상단 220×64px(홈 버튼·제목)은 비운다. 패널에 모델이 가리지 않게 `setViewOffset`(`HandPump.ts` 방식).
- **단계 버튼 5개**(`작동 원리 단계`, 누르면 그 시점으로 카메라 이동 + 부품 강조 + 설명 2~3문장. `이전/다음`):
  1. `물이 흘러온다` — 높은 곳의 물이 물홈을 따라 흘러와 바퀴 위로 떨어진다. 높은 곳에 있는 물은 위치 에너지를 가진다. (시점 `all`, 강조 물홈·수문)
  2. `물의 무게가 바퀴를 돌린다` — 날개 사이 칸에 물이 담기면 한쪽만 무거워져 바퀴가 돈다. 위치 에너지가 운동 에너지로 바뀐다. (시점 `wheel`, 강조 물레바퀴·날개)
  3. `굴통이 함께 돈다` — 바퀴 가운데를 꿴 굴통이 같이 돌며 힘을 방앗간 안으로 전한다. 기계요소로 보면 축이다. (시점 `all`, 강조 굴통·받침 기둥)
  4. `누름대가 방아채를 누른다` — 누름대가 내려오며 방아채 꼬리를 누르면, 볼씨를 받침점으로 반대쪽 공이가 올라간다. 누름대는 캠, 방아채는 지레다. (시점 `cam`, 강조 누름대·방아채·볼씨, 천천히 보기 켬)
  5. `공이가 떨어져 찧는다` — 누름대가 꼬리 끝을 벗어나면 공이가 제 무게로 떨어져 확돌 속 곡식을 찧는다. 회전 운동이 위아래 왕복 운동으로 바뀌었다. (시점 `pestle`, 강조 방아공이·확돌, 천천히 보기 켬)

### 8-2. 화면 구성 (넓은 화면)

- **숫자판**(label / value / 작은 글씨 basis. 값은 `readouts()`):
  | 항목 | 값 | basis |
  |---|---|---|
  | 물의 양 | `320 L/s` | 1초에 흘러오는 물의 부피 |

  | 바퀴에 실린 물 | `347 kg` | 지금 칸에 담겨 있는 물 |

- 버튼·칩·슬라이더 손잡이 터치 영역 44px 이상, `:focus-visible`, 숫자 `font-variant-numeric: tabular-nums`, `word-break: keep-all`. 이모지 금지(아이콘은 인라인 SVG 또는 글자).
- 강조색: 물 관련 `var(--cat-shaft)`(파랑), 캠·공이 `var(--cat-power)`. 경고 줄 `var(--warn)`.
- `prefers-reduced-motion`이면 패널 전환·강조 맥동을 끈다(기계의 움직임은 학습 내용이므로 유지).
- 다크 테마: 이름표·지시선·그래프 선이 배경과 대비 4.5:1 이상.

- 진입·재생·모든 조작에서 콘솔 에러 0. 어떤 순간에도 누름대가 방아채를 뚫고 지나가거나, 공이가 확돌 바닥을 뚫지 않는다.
- 1280×800·390×844·360×740, 밝음/다크: 가로 넘침 0, 좌상단 침범 0, 44px 미만 버튼 0, 글자 잘림 없음.
- 물의 양을 바꾸면 회전수·찧는 횟수가 5-3 표대로 바뀌고, 수문을 닫으면 60초 안에 멈춘다. 손으로 돌리기에서 바퀴가 손을 따라 앞으로만 돌고, 누름대가 빠지는 순간 공이가 **스스로** 떨어진다(드래그를 멈춰도 떨어짐).
- 이름표 토글이 즉시 듣고, 앱 설정의 이름표 끔 상태로 들어오면 꺼진 채 시작한다.
- 60fps 유지, enter/exit 20회 뒤 `__wm.selfLeak()` 증가 없음. 탭을 오래 떠났다 돌아와도(큰 dt) 바퀴가 튀지 않는다(dt 상한 1/20 s).
- `npx tsc --noEmit` — 자기 파일 에러 0.

## 12. 남은 판단 거리 (Opus가 사용자에게 확인하거나 스스로 정한다)

- 방아채를 2개로 둔 것, 누름대 끝이 방아채마다 2개(한 바퀴에 2번 찧음)인 것은 그림을 보고 정한 **모형 결정**이다. 실제 방아는 곳마다 다르다 → 화면 `이 실험의 약속`에 한 줄.
- 참고 글 본문의 `방아다리`(캠 폴로어)와 그림의 `방아채`가 같은 부품인지 자료만으로는 확정하지 못했다 → 화면에는 `방아채`만.
- 물이 내놓는 일률(모형 8.4 kW)은 자료의 "8~10마력"과 직접 비교하지 않는다(자료의 마력이 어디서 잰 값인지 나와 있지 않다).
- `수문`은 자료에 없는 조작용 부품이다. 이름이 어색하면 `물막이 판`으로 바꿔도 된다(3절 표와 이름표를 함께 바꿀 것).
