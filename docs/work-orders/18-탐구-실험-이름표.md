# 작업 지시서 18 — 탐구 실험실·507 기계 운동: 모든 부품에 이름표 + 보이기/숨기기

먼저 `00-개요.md`(공통 규칙·재질·검증), `11-탐구-실험-3종.md`의 "공통 구조"(AppMode, 패널·스타일 규칙), `17-탐구-실험-링크장치.md`(파일 소유·보고 방식)를 읽는다.
이 지시서는 **새 실험을 만드는 일이 아니다.** 이미 있는 탐구 실험 9종과 「507 기계 운동」 3D 모델에 **이름표를 빠짐없이 붙이고, 어디서나 같은 버튼으로 켜고 끄게** 만드는 일이다.

## 0. 배경 (사용자 요청 원문)

> "탐구실험실에 있는 모든 것에 이름표 넣어줘. 학생들이 부품 이름을 알고 싶을때 언제든 알게 하고 싶어. 이름표는 감추거나 감추지 않게 할 수 있어야 함."
> (추가) "507도 이름표 넣어줘."

목표 세 가지:
1. **빠짐없이** — 학생이 "이게 뭐예요?" 하고 물을 만한 부품에는 전부 이름표가 있다(나사 하나하나까지는 아님).
2. **언제든** — 단계(투어)·보기 방식·화면 크기와 상관없이 이름을 확인할 수 있다. 좁은 화면에서 자리가 없어 접힌 이름표도 점을 누르면 펼쳐진다.
3. **켜고 끄기** — 모든 실험 화면과 507 상세 화면에 같은 모양의 `이름표` 버튼이 있고, 한 번 정한 값은 다른 실험·미션·다음 방문에도 그대로다.

## 3. 공용 이름표 — 계약 (18-A가 가장 먼저 작성, 내용 고정)

### 3-1. `src/labs/common/labels.ts` — export 시그니처

```ts
import * as THREE from 'three';
import type { ModeContext } from '../../modes/types';
import '../../styles/lab-labels.css';   // 헬퍼가 스스로 불러온다 — main.ts·preview.ts를 고치지 않기 위해

export type LabelSide = 'above' | 'below' | 'left' | 'right';
/** part: 부품 이름 / point: 조인트 글자·번호(작게) / info: 수면·대기압 같은 설명 / hint: '끌어 보세요' 같은 조작 안내 */
export type LabelKind = 'part' | 'point' | 'info' | 'hint';
export type LabelTone = 'accent' | 'ok' | 'warn' | 'shaft' | 'power' | 'control';
export type Anchor = (out: THREE.Vector3) => boolean;   // out에 "월드 좌표"를 쓴다. false = 이번 프레임은 숨김

export interface LabelSpec {
  key: string;            // 한 실험 안에서 유일. DOM에 data-key로 남는다(검사 스크립트가 읽는다)
  text: string;
  at: Anchor;
  side?: LabelSide;       // 먼저 시도할 쪽. 기본 'above'
  kind?: LabelKind;       // 기본 'part'
  priority?: 1 | 2 | 3;   // 기본 2. 자리가 모자라면 3 → 2 순서로 접는다. 1은 접지 않는다
  tone?: LabelTone;       // 기본 'accent'
  always?: boolean;       // true = 토글이 꺼져도 보인다. kind 'hint'에만 쓴다
}

export interface LabelBounds { x0: number; y0: number; x1: number; y1: number }   // 화면 px

export interface LabLabelsOptions {
  /** 이름표를 놓아도 되는 영역(패널·도크·하단 시트를 뺀 3D가 보이는 곳). 없으면 화면 전체 */
  bounds?: () => LabelBounds;
  onToggle?: (visible: boolean) => void;
}

export class LabLabels {
  readonly layer: HTMLElement;          // <div class="lab-tags">, host의 첫 자식으로 붙는다
  readonly button: HTMLButtonElement;   // 실험이 자기 조작 영역에 배치한다
  constructor(ctx: ModeContext, host: HTMLElement, opts?: LabLabelsOptions);
  get visible(): boolean;               // = ctx.settings.showLabels
  setVisible(v: boolean): void;         // 설정 변경 + 저장 + 버튼 상태 + 레이어 1 동기화 + onToggle
  set(specs: LabelSpec[]): void;        // 전체 교체(단계·보기 방식이 바뀔 때). 꺼져 있어도 불러 둔다
  setText(key: string, text: string): void;                  // 글자만 바꿈(변속 단, '· 열림' 등)
  setState(key: string, state: string | null): void;         // data-state: 'open' | 'closed' | 'fire' | null
  update(): void;                       // 매 프레임 — 위치 계산·겹침 처리
  dispose(): void;                      // DOM·리스너 제거
}

/** 이름표 레이어 없이 버튼만 필요할 때(507 상세 화면) */
export function createLabelsToggle(
  ctx: ModeContext,
  opts?: { syncSceneLayer?: boolean; onToggle?: (visible: boolean) => void }   // syncSceneLayer 기본 true
): { button: HTMLButtonElement; sync(): void; dispose(): void };

export function worldAnchor(x: number, y: number, z: number): Anchor;                            // 고정 월드 좌표
export function localAnchor(obj: THREE.Object3D, x?: number, y?: number, z?: number): Anchor;    // obj의 로컬 좌표 → 월드(매 프레임 따라감)
export function midAnchor(a: Anchor, b: Anchor): Anchor;                                         // 두 점의 가운데(막대·벨트)
```

### 3-2. 동작 규칙 (18-A가 구현, 나머지는 이 규칙을 믿고 쓴다)

- **켜고 끄기**: `setVisible(v)`는 `ctx.settings.showLabels = v` → `saveSettings(ctx.settings)` → 버튼 `aria-pressed`·`title` 갱신 → `ctx.sceneMgr.setLabelsVisible(v)`(미션으로 돌아갔을 때 레이어 1이 맞게) → `.lab-tags`에 `data-on="true|false"` → `onToggle`. 버튼 클릭은 `setVisible(!visible)`. 꺼져 있으면 `always`가 아닌 이름표는 `display: none`.
- **DOM 구조(검사 스크립트·css가 이 구조에 기대므로 고정)**:
  `div.lab-tags[data-on]` > `div.lab-tag[data-key][data-kind][data-side][data-tone][data-state][data-collapsed]` > `span.lab-tag-dot` + `span.lab-tag-line` + `span.lab-tag-l`(글자).
- **모양**: 지금의 `.pf-tag`/`.cyc-tag`/`.stm-tag`를 그대로 잇는다 — 기준점에 지름 8px 점(`--accent`, 테두리 `--panel-solid`), 길이 14px 지시선, 글자는 알약 모양(`background: var(--panel-solid)`, `border: 1px solid var(--line-strong)`, `box-shadow: var(--shadow-1)`, `font-weight: 700`, `white-space: nowrap`, `word-break: keep-all`). 글자 크기 폭 700px 이상 12.5px / 미만 11.5px. `kind='point'`는 지시선 없이 점 옆에 작은 네모 글자(지금 `.lk-tag-l` 모양), `kind='info'`는 테두리 점선, `kind='hint'`는 `--accent` 테두리. `data-state='open'`은 `--ok`, `'closed'`는 `--text-faint`, `'fire'`는 `--warn` 계열(지금 증기·엔진 원리의 색 규칙 그대로). 색은 `tokens.css` 변수만 — 밝음/다크는 따로 처리하지 않는다.
- **위치·겹침**(매 프레임):
  1. `at(out)` → 카메라로 투영. 카메라 뒤(`z > 1`), `bounds` 밖, 좌상단 홈 버튼·제목 자리(`x < 240 && y < 90`)면 숨긴다.
  2. 우선순위(1 → 3), 같으면 카메라에 가까운 순으로 놓는다. 각 이름표는 `side`부터 시작해 위·아래·오른쪽·왼쪽 중 **이미 놓인 글자 상자와 4px 이상 떨어지고 `bounds` 안에 드는 첫 자리**에 놓는다. 지시선은 항상 점에서 글자 상자까지 이어진다.
  3. 놓을 자리가 없으면 **접는다**(`data-collapsed="true"` — 점만 보임). 우선순위 1은 접지 않는다(1끼리 겹칠 때만 뒤의 것을 접는다).
  4. 깜빡임 방지: 한번 정한 쪽은 그 자리가 못 쓰게 될 때까지 유지한다. 접힘/펼침은 0.25초 이상 같은 판정이 이어질 때만 바꾼다.
- **접힌 이름표 펼치기**("언제든 알게"): 점에는 지름 28px의 누름 영역(`pointer-events: auto`, `cursor: pointer`)이 있다. 접힌 점을 누르면 그 이름표가 맨 위에 펼쳐지고(겹치는 다른 것은 잠시 접힘) 4초 뒤 또는 다른 곳을 누르면 원래대로. 펼쳐진 글자 상자와 지시선은 `pointer-events: none`(3D 드래그를 막지 않는다).
- **성능**: 글자 폭은 글자가 바뀔 때만 잰다(매 프레임 `offsetWidth`·`getBoundingClientRect` 금지 — `bounds()`는 실험이 값을 캐시해서 넘긴다). `transform: translate()`만 바꾼다. 한 화면 60개까지 60fps.
- 헬퍼는 three와 DOM만 쓴다. 실험 파일·`src/ui/*`·`src/scene/*`를 import 하지 않는다(`ICON.tag`의 SVG 문자열은 `src/ui/icons.ts`에서 **읽기만** 한다 — import 는 허용).

### 3-3. 실험이 지킬 것 (18-A~D 공통)

- 자기 이름표 구현(`buildTags`/`updateTags`, 전용 스프라이트 함수, `*-tag*` css 블록)을 지우고 `LabLabels` 하나만 쓴다. `ctx.settings.showLabels`를 실험이 직접 읽지 않는다.
- `enter()`에서 `new LabLabels(ctx, wrap, { bounds })`, `update()`에서 `labels.update()`, `exit()`에서 `labels.dispose()`. 단계·보기 방식·차종 등이 바뀌면 `labels.set([...])`.
- **화면 폭으로 이름표를 줄이는 코드를 전부 지운다**(`window.innerWidth < 700 ? [] : …`, `keep` 집합, `slice(0, 4)`, `if (!small) list.push(…)`). 좁은 화면은 우선순위와 접힘이 처리한다.
- 버튼 `labels.button`은 **스크롤하거나 패널을 펼치지 않아도 항상 보이는 자리**에 둔다(4절의 실험별 "버튼 자리"). 390×844에서 다른 버튼과 겹치거나 가로 스크롤이 생기면 안 된다.
- 움직이는 부품의 이름표는 반드시 따라간다 — 기준점을 `localAnchor(움직이는 Object3D, …)` 또는 모델의 현재 자세를 읽는 함수로 준다. 고정 좌표를 한 번 계산해 두면 안 된다.
- 숨겨진 부품에는 이름표를 붙이지 않는다(모드에 따라 안 보이는 클러치/토크 컨버터, 불투명 블록 속 피스톤 등) — `at()`이 `false`를 돌려준다.
- 기준점 좌표가 지금 코드에 없으면 **모델 파일에 기준점 함수를 추가**한다(예: `partWorld(key, out)`). 이름표를 위해 3D 형상·재질·움직임은 바꾸지 않는다.

### 5-2. 어떤 부품에 이름표를 붙이는가 (규칙)

설계표(`docs/mm507-sheets/NNN.md`)의 "부품과 치수"에 이름이 나오는 것 중 다음은 **반드시 `tag()`가 있어야 한다**:
1. 힘이 들어오는 곳과 나가는 곳 — `구동 …`, `종동(피동) …`, `당기는 곳`, `짐` 등.
2. 풀리·도르래·기어·래칫·캠·크랭크·레버(지레)·링크 — 같은 종류가 여럿이면 각각(설계표의 기호를 붙여 `풀리 A`, `m1`처럼).
3. 축 — 구동축/종동축이 따로 구별될 때.
4. 벨트·줄·체인 — 모델에 하나뿐이어도 이름을 붙인다(`벨트`, `줄`).
전시대·받침·볼트·화살표에는 붙이지 않는다. 움직이는 부품의 이름표는 매 프레임 따라가게 한다(이미 `m016`~`m021`이 그렇게 한다).

- 키트가 강제하는 것: `preview.html?mm=<n>`에서 `countTags(group) === 0`이면 `console.warn('[mm507] n번: 이름표 없음')`(18-Z가 `preview.ts`에 추가). 개수 대조는 `scripts/18-mm-tags.mjs`(18-M 작성)가 한다 — 모델 파일의 `tag('…')` 글자를 정규식으로 뽑아 번호별 개수·글자 목록을 출력하고, 0개인 모델이 있으면 exit 1.
- **기존 25개 모델의 보강은 이 지시서에서 하지 않는다.** Haiku(18-H)가 설계표와 대조해 "규칙 1~4에 비해 빠진 이름표" 목록을 만들고(예: `m001`·`m002`는 풀리 2개만 있고 `벨트`가 없음, `m024`는 `구동 28`/`피동 34`만 있음 — 이 둘은 코드에서 확인함), 507 제작 흐름(지시서 16)의 다음 묶음에서 반영한다. 지시서 16의 설계표 양식 "표시" 항목에 위 규칙을 한 줄 덧붙이는 것은 Opus가 한다.

- 풍동: `BodyShape`에서 보닛·앞유리·지붕·트렁크 위치를 뽑는 방법(차고·A필러 선택에 따라 달라진다), `Tunnel`의 팬·정류기·벨트·턴테이블·받침의 좌표.
- 4절의 ★ 기준점 좌표 전부 — 형상을 보고 정한 뒤 캡처로 확인.
- `교과 용어` 병기: 이 지시서는 코드와 기존 화면 문구에서 확인되는 이름만 썼다(`차축`, `크랭크축`, `스프로킷`, `체인`, `벨트와 풀리`, `캠`, `링크`, `스프링`). 구동축·프로펠러 샤프트에 `전동축`을 괄호로 붙일지는 교과서 확인이 필요해 **붙이지 않았다** — 사용자 확인 후 결정.
