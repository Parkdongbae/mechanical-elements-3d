# 작업 지시서 06 — 학습 모드 2종: 기계요소 도감 · 단원 퀴즈

먼저 `00-개요.md`를 읽는다. 그다음 `src/modes/types.ts`(인터페이스), `src/styles/tokens.css`(디자인 토큰),
`src/data/elements.ts`(부품 22종·4분류), `src/data/machines.ts`(미션), `src/models/factory.ts`의 `buildPart/normalizePart/disposeObject`,
`src/scene/SceneSetup.ts`의 `flyTo`.

소유 파일: `src/modes/Encyclopedia.ts`, `src/modes/Quiz.ts`(둘 다 지금은 스텁), `src/data/encyclopedia.ts`, `src/data/quiz.ts`, `src/styles/modes.css`.
필요하면 `src/modes/` 아래 보조 파일 추가 가능. `main.ts`·`index.html`·다른 css는 수정 금지(메인이 연결한다).

## 연결 방식 (메인이 구현)

- 메인이 `new Encyclopedia()` / `new Quiz()`를 만들고 홈 화면에서 진입 시 `enter(ctx)`, 나갈 때 `exit()`, 매 프레임 `update(dt, t)`를 호출한다.
- `ctx.root`는 화면 전체를 덮는 `pointer-events: none` 컨테이너. 모드가 만든 패널에 `pointer-events: auto`를 준다.
  패널이 없는 영역은 3D 캔버스 조작(OrbitControls)이 그대로 통과한다.
- 상단 좌측(0~64px 높이, 왼쪽 220px)은 메인의 "홈" 버튼과 제목 자리이므로 비워 둔다.
- `src/styles/modes.css`는 메인이 import 한다. 클래스 접두어 `enc-`, `quiz-`. 색·간격·그림자는 **tokens.css 변수만** 사용(테마 자동 대응).
- `exit()`에서 DOM, 씬 오브젝트(`disposeObject`), 리스너, 타이머를 전부 정리한다. 여러 번 enter/exit 해도 누수·중복이 없어야 한다.

## 1) 기계요소 도감 — `Encyclopedia`

목적: 미션에서 스쳐 지나간 22종을 **하나씩 크게 돌려 보며** 분류·역할·쓰임새를 익힌다.

- 레이아웃(데스크톱): 좌측 목록 패널(폭 ~300px) — 4분류 탭(결합용/축용/제어용/전동용, 분류색 점) + 해당 분류 부품 목록(썸네일 `ctx.thumbs.get(part)` + 이름).
  우측 정보 패널(폭 ~340px) — 분류 칩, 이름, 역할(`part.role`), **쓰이는 곳**, **핵심 포인트**, **헷갈리기 쉬운 요소와의 차이**, 이 부품이 나오는 미션 목록.
  가운데는 3D: 선택한 부품이 턴테이블 위에서 천천히 자전(드래그하면 OrbitControls로 직접 회전, 조작 중엔 자전 일시정지).
- 태블릿·모바일(폭 < 820px): 목록은 하단 가로 스크롤 스트립, 정보는 접을 수 있는 바텀시트.
- 3D: `normalizePart(buildPart(part.builder), 2.2)`를 y≈1.4에 띄우고, 아래에 얇은 원형 받침(턴테이블)과 분류색 링. 부품 전환 시 짧은 스케일/페이드 전환.
  진입 시 `ctx.sceneMgr.flyTo({ pos: [2.8, 2.6, 4.6], target: [0, 1.35, 0] })`.
- 이전/다음 버튼과 좌우 화살표 키, "본 부품 n/22" 진행 표시(localStorage `mech3d-seen-v1`).
- 데이터 `src/data/encyclopedia.ts`: `Record<partId, { usedIn: string[]; keyPoint: string; versus?: { partId: string; diff: string } }>` — 22종 전부.
  내용은 **중학교 기술·가정(2022 개정) '기계의 구성과 동력 전달'** 수준, `elements.ts`의 role 문구·명칭과 모순 없이. 확실하지 않은 사실은 쓰지 않는다.
  예) 평행 핀 vs 테이퍼 핀(굵기 일정/점점 가늘어짐), 차축 vs 전동축(고정되어 받침/함께 회전하며 동력 전달), 평 기어 vs 헬리컬 기어(소음·진동), 벨트 vs 체인(미끄럼/정확).

## 2) 단원 퀴즈 — `Quiz`

목적: 10문제 한 세트로 분류·명칭·쓰임새를 점검.

- 문제 유형(섞어서 출제, 매번 무작위 10문제):
  1. **이름 맞히기**: 3D로 부품을 보여 주고 4지선다(같은 분류의 유사 부품을 오답으로 — 예: 핀 3종끼리, 기어 5종끼리).
  2. **분류 맞히기**: 부품 이름+3D → 결합용/축용/제어용/전동용 중 선택.
  3. **쓰임새 맞히기**: "두 축의 거리가 멀고 미끄럼 없이 정확하게 전달해야 한다. 알맞은 것은?" 같은 상황형 4지선다(데이터 `src/data/quiz.ts`에 20문항 이상).
  4. **O/X**: 개념 진위(데이터에 10문항 이상, 해설 포함).
- 흐름: 시작 화면(문제 수, 최고 점수) → 문제(진행 바 n/10, 선택지 버튼) → 즉시 채점(정답 초록/오답 빨강 + 한 줄 해설, `ctx.playSound`) → "다음" →
  결과(점수, 틀린 문제 복습 목록 — 각 항목에서 해당 부품 3D 다시 보기, "다시 풀기", "도감에서 복습"은 생략하고 "홈으로" = `ctx.goHome()`).
- 3D: 유형 1·2는 도감과 같은 방식으로 부품 표시(정답 공개 전에는 이름 라벨 없음). 유형 3·4는 정답 공개 후 관련 부품을 보여 준다.
- 최고 점수 저장: localStorage `mech3d-quiz-v1` = `{ best: number, plays: number }`.
  `src/modes/Quiz.ts`에서 `export function getQuizBest(): { best: number; plays: number }`를 export(홈 화면 표시용).
  같은 방식으로 `src/modes/Encyclopedia.ts`에서 `export function getSeenCount(): number`.
- 레이아웃: 문제 패널은 우측(데스크톱 폭 ~400px) 또는 하단 시트(모바일). 3D가 가려지지 않게.

## UI 품질
- 버튼 최소 터치 영역 44px, 키보드 포커스 표시(`:focus-visible`), 버튼은 `<button>`.
- 패널: `background: var(--panel); backdrop-filter: blur(14px); border: 1px solid var(--line); border-radius: var(--radius-l); box-shadow: var(--shadow-1)`.
- 글자: 본문 15px, 보조 13px `var(--text-dim)`, 제목 20~22px 700. 이모지는 아이콘 대용으로 남발하지 않는다.
- 텍스트가 길어도 넘치지 않게(줄바꿈 `word-break: keep-all`), 폭 360px 화면에서도 가로 스크롤 없음.

## 검증
메인 UI가 아직 연결 전일 수 있으므로, 개발용 진입점이 있다: `preview.html?mode=enc` / `preview.html?mode=quiz` (메인이 preview.ts에 추가해 둠 — 없으면 보고).
`node scripts/shot.mjs "preview.html?mode=enc" shots/06-enc.png 4000`, 모바일 폭 `... 4000 390 844`, 다크 `&theme=dark`. 직접 열어 확인.
퀴즈 상호작용 검증이 필요하면 `scripts/` 아래에 자체 playwright 스크립트(파일명 `06-*.mjs`)를 만들어 클릭 흐름을 캡처한다(`scripts/shot.mjs` 참고, `channel: 'chrome'`).
