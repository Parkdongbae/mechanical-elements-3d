## 0. 사용자 결정 사항
- 새 파트 **「507 기계 운동」**: Henry T. Brown의 책(1868) 507개 운동 전체를 **목록(원본 판화 + 한글 설명)** 으로 열람, **1번부터 책 순서대로 3D 작동 모델** 제작. 1차 목표 **1~100번**, 완료 시 GitHub 푸시. 이후 몇 주에 걸쳐 계속.
- 책의 **역사적 가치** 소개 포함. 책 내용만으로 부족하면 학생이 이해하기 쉽게 보충 설명을 더한다(지어낸 사실 금지).
- **역할**: 코드는 전부 **GLM**(opencode, `zai-coding-plan/glm-5.3-flash` — 사용자 지시로 flash만 쓴다)이 작성한다. Claude는 **작업 지시서·설계표 작성, 검증, 수정**만 한다(최종 검증·수정은 Opus). 자료(전사·번역)는 Claude가 준비한다(그림을 읽어야 하므로).
- 참고 사이트 507movements.com의 애니메이션·그림은 **가져오지 않는다**(그 사이트 제작자의 저작물). '함께 보면 좋은 곳'으로 링크만 건다.

## 3. 모델 규약 — 모든 운동이 같은 틀을 쓴다

### 3-1. 전시 형식
- 모든 운동은 **박물관의 벽걸이 전시 모형**처럼 만든다: 나무 받침 + 세워진 나무 뒤판 앞에 황동·강철 기구.
- **구도는 판화와 같게**: 판화의 정면 = 화면 정면(+Z에서 바라봄). 기구는 XY 평면(z = 0 근처)에 놓고, 판화에서 종이에 수직인 축은 Z 방향이다.
- 전시 영역: 폭 4.0 × 높이 2.8, 중심 (0, 1.75, 0). 바닥 y = 0. 뒤판 앞면 z = -0.30. 기구는 z ∈ [-0.25, 0.6].
- 판화의 비율을 따른다(풀리 크기 비, 축 간 거리 비). 치수는 설계표가 정한다.
- 색: 뒤판·받침 `wood`, 축·핀 `steel`, 풀리·기어 `brass`(구동 쪽은 약간 붉은 `bronze`로 구분), 벨트 `rubber`(짙은 갈색 가죽 톤), 프레임 `castIron`, 추 `darkSteel`. 강조가 필요하면 `glow`.
- 학생이 **회전이 보이도록**: 풀리·기어에는 스포크/구멍/표시점이 있어야 한다. 벨트에는 이음매 표시가 흘러야 한다.

### 3-2. 타입 (`src/mm507/types.ts`)
```ts
import type * as THREE from 'three';
import type { CameraView } from '../scene/SceneSetup';

export interface MovementNote { label: string; value: string }

export interface MovementModel {
  /** 씬에 추가할 루트. 전시대 포함 */
  group: THREE.Group;
  /** 매 프레임. dt = 초, speed = 사용자 속도 배율(0~3, 음수면 역회전) */
  update(dt: number, speed: number): void;
  /** 상세 화면 수치 패널(선택) — 매 프레임 읽으므로 가볍게 */
  notes?(): MovementNote[];
  /** 권장 시점(없으면 기본 정면 시점) */
  view?: CameraView;
  /** 직접 만든 텍스처 등 해제(지오메트리·재질은 공용 disposeObject 가 처리) */
  dispose?(): void;
}

/** src/mm507/models/mNNN.ts 는 이 함수를 default export 한다 */
export type MovementBuilder = () => MovementModel;
```
- 모델 파일은 **상태를 클로저에 담는 함수형**으로 쓴다(클래스 금지 — 파일이 짧고 비슷해진다).
- `update`는 누적 각도(`theta += omega * speed * dt`)에서 **모든 부품의 자세를 다시 계산**한다(증분 누적 오차·역회전 문제 방지).
- 기본 구동 각속도 `OMEGA = 1.6 rad/s`(약 15 rpm). 설계표가 따로 정하면 그 값을 쓴다.

## 5. 역사 소개에 쓸 내용 (확인된 범위만)
아래는 **이 스캔본의 표제지·판권지·서문을 직접 읽어 확인한 사실**이다(`data/mm507/front.json`, `preface.json`). 소개 글은 이 범위 안에서 쓴다.
- 제목: *Five Hundred and Seven Mechanical Movements*(507가지 기계 운동). 표제지의 부제는 동역학·수력학·유체 정역학·기체 역학·증기 기관·제분 및 기타 기어 장치·프레스·시계 장치·그 밖의 여러 기계에서 중요한 것을 모두 담았고, "이전에 발표된 적 없는 운동과 최근에야 쓰이기 시작한 운동"도 포함한다고 밝힌다.
- 지은이: 헨리 T. 브라운(Henry T. Brown) — 표제지에 "*American Artisan* 편집자"로 적혀 있다.
- 펴낸 곳: 뉴욕, Brown, Coombs & Co.(*American Artisan* 사무실, 브로드웨이 189번지).
- 연도: 판권지에 **1868년 저작권 등록**. 우리가 가진 스캔본은 표제지에 **1871년**이라고 찍힌 인쇄본이다(코넬 대학교 도서관 소장본 스캔). → "1868년에 처음 나온 책(이 자료는 1871년 인쇄본)"으로 쓴다.
- 서문에서 저자가 밝힌 것: ① 기계 운동을 한데 모은 책이 오랫동안 필요했기에 엮었다 ② 내용은 먼저 잡지 *American Artisan*에 다섯 권에 걸쳐 실렸다 ③ 수록된 운동의 4분의 1 이상이 새로운 것이고, 그때까지 미국에서 나온 어떤 책보다 약 세 배 많은 운동을 담았다 ④ 분류는 완전하지 않지만, 자세한 색인과 "그림을 설명과 마주 보게 놓은 구성"으로 찾아보기 쉽게 했다.
- 구성: 왼쪽 쪽에 판화 9~10개, 오른쪽 쪽에 같은 번호의 설명. 운동은 122쪽(507번)에서 끝나고 뒤에는 당시의 광고가 실려 있다.
- 가치(설명 방향 — 평가이므로 단정하지 않는 말투로): 컴퓨터도 동영상도 없던 시대에 발명가·기술자가 "이런 움직임을 만들려면 어떤 기구를 쓰면 될까"를 찾아보던 그림 사전. 150년이 지난 지금의 기계에도 같은 원리가 들어 있다(자전거의 체인, 시계의 탈진기, 엔진의 크랭크). 책은 공유 저작물이어서 누구나 읽고 다시 만들 수 있다.
- **쓰지 않는 것**: 판매 부수, 판(版) 수, 저자의 생몰년·경력 세부, "최초"·"가장 유명한" 같은 단정 — 이 자료로 확인되지 않는다.

## 6. 운동 1개의 작업 절차와 검증

### 6-1. 설계표 (`docs/mm507-sheets/NNN.md`, Claude 작성)
판화와 원문을 Claude가 직접 보고 쓴다. 형식:
```
# NNN 한글 이름
판화 요약 / 부품과 치수(키트 호출 수준으로) / 동작(구동 부품, 각속도, 각 부품 자세를 theta 의 함수로) /
표시(화살표·이름표) / notes / 확인할 것(캡처 두 시점에서 무엇이 달라야 하는지) / [키트 추가](있을 때만)
```

### 6-2. GLM 실행 (운동 1개 = 1회)
`bash scripts/mm507/glm_run.sh <n>` — 프롬프트 요지: 이 문서의 3장 + `docs/mm507-sheets/NNN.md` + 본보기 `src/mm507/models/m001.ts` + `src/mm507/kit/index.ts`를 읽고 `src/mm507/models/mNNN.ts` 하나만 작성. `npx tsc --noEmit` 통과, `node scripts/shot.mjs "preview.html?mm=<n>&t=1" shots/mm/NNN-a.png`와 `t=1.6`으로 `-b.png` 저장(콘솔 에러 없음).

### 6-3. 검증 (10개 묶음마다, Opus)
캡처 2장 + 판화(`public/mm507/fig/NNN.png`)를 나란히 열어 확인한다.
- [ ] 판화와 같은 구도·비율인가(무엇을 그린 것인지 한눈에 대응되는가)
- [ ] 부품이 떠 있거나 박혀 있지 않은가, 전시 영역 안에 있는가
- [ ] 원문 설명대로 움직이는가(회전 방향, 속도비, 왕복 범위, 간헐 동작의 순서)
- [ ] 두 캡처 사이에 움직여야 할 것이 움직였는가, 벨트 표시가 흘렀는가
- [ ] 재질 라이브러리·키트만 썼는가, 파일이 규약(함수형, 절대 자세 계산)을 지키는가
- 미달이면 Opus가 그 파일(필요하면 키트)을 직접 고친다. 같은 실수가 반복되면 설계표 양식이나 이 문서를 고친다.
