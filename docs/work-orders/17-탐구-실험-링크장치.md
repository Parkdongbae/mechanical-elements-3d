## 0. 배경 (사용자 요청 원문)

> "탐구 실험실에 링크 장치 추가. 여러 종류의 링크를 사용자가 선택해서 작동시키는 것입니다. https://motiongen.io/ 홈페이지 화면이 링크를 활용한 것입니다. 다양한 링크의 활용을 학생들이 체험하게 하고 싶습니다."

motiongen.io 첫 화면은 평면 링크 장치(막대 + 핀 이음 + 고정 받침)가 움직이면서 **커플러 위 한 점이 그리는 곡선**을 보여 주는 화면이다(걷는 로봇, 그림 그리는 장치, 집게 등).
**발상만 참고한다. 그 사이트의 모양·색·문구·이미지·코드는 가져오지 않는다.**

목표: 학생이 링크 장치 10종 + "직접 만들기"를 골라서 **돌려 보고, 손으로 끌어 보고, 점이 그리는 자취를 보고, 어디에 쓰이는지** 알게 한다.
이 앱에는 이미 링크가 들어간 미션(와이퍼, 선풍기 목, 핸들, 우산, 피아노, 사다리)이 있다 — 그 미션에서 "링크"를 장착만 해 본 학생이 여기서 원리를 확인한다.

## 3. 용어 (화면 문구는 이 표의 말만 쓴다)

이 앱의 기존 설명(`src/data/elements.ts`의 `link`): "여러 막대를 핀으로 연결해 회전 운동을 다른 운동으로 바꿉니다. 자동차 와이퍼가 대표적이에요." — 이 정의와 어긋나는 말을 쓰지 않는다. 교과서 4분류·명칭은 바꾸지 않는다(`00-개요.md` 4-1).

| 화면 표기 | 뜻 (처음 나올 때 괄호 풀이를 붙인다) | 코드의 role |
|---|---|---|
| 링크 | 핀으로 이어진 막대 하나하나 | — |
| 링크 장치 | 링크 여러 개를 핀으로 이어 운동을 바꾸는 장치 | — |
| 고정 링크 | 움직이지 않는 링크(받침·틀) | `ground` |
| 크랭크 | 한 바퀴 빙 도는 링크 | `input`(대부분) |
| 로커(흔들 링크) | 일정한 각도 안에서 왔다 갔다 하는 링크 | `output` 또는 `input` |
| 커플러(연결 링크) | 움직이는 두 링크를 이어 주는 링크 | `coupler` |
| 슬라이더(미끄럼 블록) | 곧은 길을 따라 미끄러지는 부품 | `output` |
| 4절 링크 장치 | 링크 4개(고정 링크 포함)를 핀 4개로 이은 장치 | — |
| 구동 링크 / 따라 움직이는 링크 | 힘을 넣는 링크 / 그 결과로 움직이는 링크 | `input` / `output` |
| 그라스호프 조건 | 가장 짧은 링크 + 가장 긴 링크 ≤ 나머지 두 링크의 합 | — |
| 전달각 | 커플러와 따라 움직이는 링크 사이의 각. 90°에 가까울수록 힘이 잘 전해진다 | — |
| 사점 | 두 링크가 한 줄로 펴지거나 접혀 더 밀 수 없는 위치 | — |
| 자취 | 한 점이 움직이며 그리는 곡선 | — |

"그라스호프 조건", "전달각", "사점"은 중학교 교과 용어가 아니다 — 화면에서 `더 알아보기` 성격으로 다루고 반드시 쉬운 풀이를 함께 쓴다.

## 4. 공통 계약 — `src/labs/linkage/types.ts` (Opus가 먼저 작성, 내용 고정)

```ts
// 링크 장치 실험 공통 타입 — 기구는 "조인트를 차례로 구하는 순서(Step)"로 적는다. 런타임 import 없음.
export type Vec2 = readonly [number, number];
export type Role = 'ground' | 'input' | 'coupler' | 'output' | 'link';

export type Step =
  | { k: 'fix'; id: string; at: Vec2 }                                   // 고정 받침
  | { k: 'crank'; id: string; o: string; r: number }                     // 입력 q(rad): o + r(cos q, sin q)
  | { k: 'push'; id: string; from: Vec2; dir: Vec2 }                     // 입력 q(cm): from + q·dir (dir은 단위 벡터)
  | { k: 'free'; id: string }                                            // 입력 점 그대로(2자유도: 팬터그래프)
  | { k: 'rr'; id: string; a: string; ra: number; b: string; rb: number; side: 1 | -1 } // 원–원 교점. side=+1 은 a→b 방향의 왼쪽
  | { k: 'rp'; id: string; a: string; r: number; p: Vec2; dir: Vec2; side: 1 | -1 }     // 원–직선 교점(슬라이더). side=+1 은 dir 쪽으로 더 먼 교점
  | { k: 'rigid'; id: string; a: string; b: string; u: number; v: number };             // 같은 강체 위의 점: a + u·ê + v·n̂ (ê=(b−a)/|b−a|, n̂=ê를 반시계 90°)

export type InputSpec =
  | { kind: 'rotate'; q0: number }                                       // 한 바퀴 도는 입력(rad)
  | { kind: 'swing'; min: number; max: number; q0: number }              // 범위 안에서 왕복(rad)
  | { kind: 'slide'; min: number; max: number; q0: number }              // 범위 안에서 왕복(cm)
  | { kind: 'point'; center: string; rMin: number; rMax: number; paths: { name: string; pts: Vec2[] }[] }; // 점을 끌거나 정해진 도형을 따라감
export type InputValue = number | Vec2;

export interface Bar { a: string; b: string; role: Role; layer: number; via?: string[]; slot?: boolean }
export interface Plate { pts: readonly [string, string, string]; role: Role; layer: number } // 세 점이 한 몸인 삼각 링크
export interface Rail { at: string; p: Vec2; dir: Vec2; min: number; max: number; style: 'piston' | 'ram' | 'block'; layer: number }
export interface Decor { kind: 'wheel' | 'blade' | 'tire' | 'slotBlock' | 'floor' | 'jawPad'; a: string; b?: string; size: number; ang?: number }
export interface TracePoint { id: string; label: string }

export interface MechanismDef {
  id: string; name: string; unit: 'cm' | '단위';
  oneLine: string;          // 목록 카드 한 줄
  how: string[];            // 어떻게 움직이나 (2~3문장)
  uses: string[];           // 어디에 쓰일까? (2~3개)
  watch: string;            // 이것을 눈여겨봐요 (1문장)
  steps: Step[]; input: InputSpec; handle: string;   // handle: 손으로 끄는 조인트 id
  bars: Bar[]; plates?: Plate[]; rails?: Rail[]; decor?: Decor[];
  trace: TracePoint[];      // 첫 번째가 기본 자취
  topView?: boolean;        // 위에서 본 그림(조향)임을 화면에 표시
}

export interface Pose { ok: boolean; q: InputValue; pts: Record<string, Vec2>; failAt?: string } // ok=false: failAt 조인트를 조립할 수 없음
export interface Bounds { minX: number; maxX: number; minY: number; maxY: number }
export interface Sweep {
  poses: Pose[];            // 입력 전 구간을 고르게 나눈 표본(조립 가능한 것만)
  qs: number[];             // 각 표본의 입력값(rad 또는 cm, point 입력은 경로 진행 0~1)
  full: boolean;            // 입력 링크가 한 바퀴 다 도는가
  qMin: number; qMax: number; // 조립 가능한(또는 지정된) 입력 범위
  bounds: Bounds;           // 모든 조인트가 쓸고 지나가는 영역(자동 배율용)
}
export interface Readout { key: string; label: string; value: string; basis?: string } // basis: 계산 근거 한 줄
export type GrashofKind = 'crank-rocker' | 'double-crank' | 'double-rocker' | 'rocker-crank' | 'change-point' | 'non-grashof' | 'impossible';
export interface GrashofResult { kind: GrashofKind; s: number; l: number; p: number; q: number; label: string; note: string }
```

`types.ts`·`solver.ts`·`mechanisms.ts`·`metrics.ts`는 **three·DOM을 import 하지 않는 순수 TS**로 쓴다(런타임 import는 이 네 파일끼리만, 확장자 `.ts`를 붙이지 않는 이 저장소 방식 그대로). `enum`·`namespace`·생성자 매개변수 속성은 쓰지 않는다 — 검사 스크립트가 번들 없이 읽을 수 있게.

### 5-1. `solver.ts` — export 시그니처(고정)

export function inputFromPoint(def: MechanismDef, pose: Pose, p: Vec2): InputValue; // 드래그한 기구 좌표 → 입력값(범위 안으로 제한)

### 5-2. 풀이 규칙 — **가짜 금지**

- `steps`를 순서대로 푼다. 모든 링크 길이는 항상 일정해야 한다(원–원 교점, 원–직선 교점을 닫힌 식으로 계산. 반복법·보간·"그럴듯한 각도" 금지).
- **조립 불가 검출**: `rr`에서 두 원이 만나지 않으면(중심 거리 > ra+rb 또는 < |ra−rb|), `rp`에서 직선까지 거리 > r 이면 `ok:false, failAt:id`를 돌려준다. 허용 오차는 `1e-9 × 기구 크기`, 그 안의 음수 제곱근만 0으로 본다. **해가 없는데 가장 가까운 점으로 대충 그리는 것 금지.**
- **가지(조립 방향) 연속성**: 교점은 항상 2개다. 첫 프레임은 `side`로 고르고, 그 뒤로는 **직전 두 프레임으로 예측한 위치(2·prev − prev2)에 가까운 교점**을 고른다(prev2가 없으면 prev에 가까운 쪽). 두 후보가 예측점에서 같은 거리(1e-6 이내)면 현재 side 부호를 유지한다.
  이 규칙이어야 평행 크랭크가 한 줄로 펴지는 순간(변환점)을 **평행사변형인 채로** 지나간다. `side`를 매 프레임 고정해서 고르면 안 된다(뒤집힘).
- **큰 입력 변화**: 드래그나 스크러버로 입력이 한 번에 2° 넘게(슬라이드는 범위의 1/90 넘게) 바뀌면 `advance`가 1° 이하로 잘게 나눠 차례로 푼다(가지를 건너뛰지 않게). 중간에 조립이 안 되는 곳을 만나면 **그 직전 자세에서 멈추고** `ok:false`를 알린다.
- `sweep`: 입력 범위를 n등분해 앞에서부터 차례로 풀어 표본·범위·`bounds`를 만든다. `rotate` 입력인데 중간에 조립이 안 되는 구간이 있으면 `full=false`와 조립 가능한 구간(`qMin~qMax`, q0가 들어 있는 구간)을 돌려준다.
- `inputFromPoint`: crank는 `atan2(p − o)`(swing이면 범위로 자르기, rotate면 직전 각에서 가장 가까운 회전수로 풀기), push는 `dir` 위로 정사영, free는 `center`에서의 거리를 `rMin~rMax`로 자른 점.
- 4절 링크 입력 범위(닫힌 식): `A=(a cosθ, a sinθ)`, `|AO4|² = a² + d² − 2ad cosθ`. 조립 조건 `|b−c| ≤ |AO4| ≤ b+c` →
  `(a²+d²−(b+c)²)/(2ad) ≤ cosθ ≤ (a²+d²−(b−c)²)/(2ad)`. 이 구간이 [−1, 1]을 다 덮으면 한 바퀴, 겹치지 않으면 조립 불가, 아니면 0° 둘레 한 구간·180° 둘레 한 구간·위아래 두 구간(위쪽 것을 쓴다) 중 하나.
- `grashof`: 길이를 정렬해 `s ≤ p ≤ q ≤ l`.
  `l ≥ s+p+q` → `impossible`(조립 불가). `s+l < p+q` 이면 가장 짧은 링크가 고정 링크(d) → `double-crank`(이중 크랭크), 입력(a) → `crank-rocker`(크랭크-로커), 커플러(b) → `double-rocker`(이중 로커), 출력(c) → `rocker-crank`("크랭크-로커 — 단, 한 바퀴 도는 쪽은 c예요").
  `s+l = p+q`(오차 1e-9) → `change-point`("경계 — 한 줄로 접히는 순간이 있어요. 평행 크랭크가 여기에 속해요"). `s+l > p+q` → `non-grashof`("이중 로커 — 어느 링크도 한 바퀴 돌지 못해요").

- 검산값: θ=−15° → P=(6.004, −0.068), θ=+15° → P=(5.996, 3.039), θ=±26° → P=(5.950, 4.023) / (6.091, −1.303). |y−1.5| ≤ 2 구간에서 |x−6| ≤ 0.014.

### 6-8. `pantograph` 팬터그래프 — "따라 그리면 2배로"
- 2자유도 기구: 학생이 추적점 `P`를 끌거나, 정해진 도형을 따라가게 한다.
- steps: `O fix(0,0)`, `P free`, `A rr(a=O, ra=4, b=P, rb=4, side=+1)`, `E rigid(O, A, u=8, v=0)`, `D rr(a=E, ra=4, b=P, rb=4, side=+1)`, `Q rigid(E, D, u=8, v=0)`(펜).
- bars: O–E(`via:['A']`, 길이 8), E–Q(`via:['D']`, 길이 8), A–P(4), D–P(4). A–E–D–P는 한 변 4인 마름모(평행사변형).
- 입력 `point`: center=`O`, rMin=2.5, rMax=7.2, paths = 삼각형 `(3,−2.5)(5,−2.5)(4,−4.5)`, 사각형 `(3,−2.5)(5,−2.5)(5,−4.5)(3,−4.5)`, 원(중심 (4,−3.5), 반지름 1 — 48각형으로). 자동 재생은 고른 도형의 둘레를 일정한 빠르기로 돈다. handle=`P`.
- 자취: `P`(작은 도형)와 `Q`(큰 도형) **둘 다** 그린다.
- 쓰임: 그림·지도·글자를 일정한 비율로 키우거나 줄여 옮겨 그리는 도구, 같은 원리의 조각기. 전철 지붕에서 전깃줄에 닿는 집전 장치도 모양이 닮아 '팬터그래프'라고 부른다.
- 숫자판: **배율 = OE ÷ OA = 8 ÷ 4 = 2** / P가 움직인 거리 / Q가 움직인 거리 / 두 거리의 비(2.00) / 지금 |OQ| ÷ |OP|.
- 검산값: 모든 자세에서 Q = 2·P(오차 1e-9). P=(4,−3.5) → A=(3.969, 0.500), E=(7.937, 1.000), Q=(8,−7).

### 6-9. `jansen` 얀센의 걷는 다리
- 네덜란드 예술가 테오 얀센의 '해변 동물(Strandbeest)' 다리. 길이는 **얀센이 공개해 널리 알려진 수치(a~m)** 를 그대로 쓰고 화면에도 그렇게 밝힌다:
  a=38, b=41.5, c=39.3, d=40.1, e=55.8, f=39.4, g=36.7, h=65.7, i=49, j=50, k=61.9, l=7.8, m=15.
- steps(단위 그대로): `O fix(0,0)`(고정 받침), `Oc fix(38, 7.8)`(크랭크 중심 — 받침에서 가로 a, 세로 l), `M crank(Oc, 15)`(m), `U rr(a=O, 41.5, b=M, 50, side=+1)`(b, j), `W rr(a=O, 39.3, b=M, 61.9, side=−1)`(c, k), `L rr(a=O, 40.1, b=U, 55.8, side=+1)`(d, e), `K rr(a=L, 39.4, b=W, 36.7, side=−1)`(f, g), `F rr(a=K, 65.7, b=W, 49, side=−1)`(h, i — 발끝).
- plates: 위 삼각형 O–U–L(b, e, d), 아래 삼각형 K–W–F(g, i, h). bars: Oc–M(input), M–U(j), M–W(k), O–W(c), L–K(f), 고정 링크 O–Oc(ground). decor: `floor`(y = 발끝 최저 높이에 바닥 선). 입력 `rotate`, q0=0°. handle=`M`. unit `단위`.
- 자취: `F`(발끝 — 아래가 평평하고 위가 둥근 곡선).
- 쓰임: 바람의 힘으로 해변을 걷는 얀센의 움직이는 조형물, 이를 본뜬 걷는 로봇·장난감. 바퀴 대신 다리로 울퉁불퉁한 곳을 걷는 방법. (화면에 "크랭크 하나만 돌리면 발끝이 '땅을 밀고 → 들어 올리고 → 앞으로 내딛는' 길을 그려요".)
- 숫자판: 크랭크 각 / 발끝 높이(가장 낮은 곳 기준) / **땅에 닿아 있는 구간**(발끝 높이 ≤ 1 단위인 크랭크 각의 범위와 비율) / 보폭(그 구간의 가로 길이) / 발을 드는 높이(최대 높이). 전부 `sweep`에서 잰다.
- 그래프: θ – 발끝 높이.
- 선택(시간이 남으면): `다리 한 쌍 보기` — 같은 크랭크에 180° 어긋난 다리를 하나 더(받침은 같고 크랭크 각만 +180°) 흐리게 그려, 한 발이 뜰 때 다른 발이 땅에 있음을 보여 준다.
- 검산값: 한 바퀴 내내 조립 가능, 가지 뒤집힘 없음. θ=0° → M=(53, 7.8), U=(13.99, 39.07), W=(11.05, −37.72), L=(−36.79, 15.94), K=(−21.23, −20.25), F=(−5.16, −83.96). θ=90° → F=(30.31, −82.59), 180° → F=(4.27, −65.72), 270° → F=(−32.67, −81.84). 발끝 y 범위 −84.03~−61.58(드는 높이 22.4), x 범위 −33.5~34.4. 높이 ≤ 1인 구간은 크랭크 286.5°→81°의 약 155°(43%), 보폭 약 57.3.

### 6-10. `gripper` 집게 — "밀고 당기면 벌어지고 오므려진다"
- steps: `C push(from=(0,0), dir=(1,0))`, `F1 fix(4, 2.5)`, `F2 fix(4, −2.5)`, `J1 rr(a=C, 2.5, b=F1, 1.5, side=−1)`, `J2 rr(a=C, 2.5, b=F2, 1.5, side=+1)`, `T1 rigid(F1, J1, u=1.657, v=5.293)`, `T2 rigid(F2, J2, u=1.657, v=−5.293)`.
- 입력 `slide` 1.5~2.5 cm, q0=2.0. handle=`C`. rails: `C`, p=(0,0), dir=(1,0), min=0.8, max=3.2, style `block`(밀대).
- bars: C–J1, C–J2(coupler). plates: F1–J1–T1, F2–J2–T2(집게 팔 — ㄱ자 지렛대, output). decor: `jawPad`(T1, T2 끝의 고무 패드).
- 자취: `T1`, `T2`.
- 쓰임: 로봇 손(그리퍼), 멀리 있는 물건을 집는 집게 장난감. 밀대 하나의 직선 운동이 두 팔의 회전으로 바뀐다(슬라이더-크랭크를 거꾸로, 두 개를 마주 보게 쓴 것).
- 숫자판: 밀대 위치 / **집게 벌어진 폭** = T1.y − T2.y / 팔 길이 비 = |F1T1| ÷ |F1J1| = 5.546 ÷ 1.5 = 3.70("끝은 3.7배 크게 움직여요").
- 그래프: 밀대 위치 – 벌어진 폭.
- 검산값: q=1.5 → J1=(3.78, 1.02), T1=(9.00, 0.10)(폭 0.20, 닫힘), q=2.0 → T1=(9.51, 1.86), q=2.5 → T1=(9.45, 3.53)(폭 7.06).

### 6-11. `custom` 직접 만들기 — 4절 링크와 그라스호프 조건
- `fourbar(a, b, c, d, u, v)`: `O2 fix(0,0)`, `O4 fix(d,0)`, `A crank(O2, a)`, `B rr(A, b, O4, c, side=+1)`, `P rigid(A, B, u, v)`. 입력은 `inputRange` 결과에 따라 `rotate` 또는 `swing`(q0는 범위의 가운데).
- 조작: 길이 슬라이더 4개 — 구동 링크 a, 커플러 b, 따라 움직이는 링크 c, 고정 링크 d (각 1~12, 0.5 간격, 기본 3·9·7·10). 커플러 점 슬라이더 2개 — 커플러를 따라 u(0~b), 옆으로 v(−6~6), 기본 u=4.5, v=3. 슬라이더를 움직이면 **즉시** 다시 조립된다(끊김 없이).
- 프리셋 버튼(누르면 슬라이더가 그 값으로): 크랭크-로커 `3·9·7·10` / 이중 크랭크 `5·6·7·3` / 이중 로커 `7·3·6·8` / 평행 크랭크 `3·8·3·8` / 조건 불만족 `5·4·6·10` / 조립 불가 `2·3·3·10`.
- 표시(핵심): **그라스호프 식을 지금 숫자로** — `가장 짧은 링크 s + 가장 긴 링크 l` 과 `나머지 두 링크 p + q` 를 막대 2개와 식으로 나란히(예: `3 + 10 = 13 ≤ 9 + 7 = 16 → 만족`), 그 아래 판정 배지: `크랭크-로커` / `이중 크랭크` / `이중 로커` / `조립 불가` (경계·불만족·"도는 쪽은 c"는 배지 아래 한 줄 설명으로 — 5-2의 `label`/`note`).
  어느 링크가 가장 짧은지에 따라 판정이 달라짐을 한 줄로: "가장 짧은 링크가 구동 링크면 크랭크-로커, 고정 링크면 이중 크랭크, 커플러면 이중 로커".
- **조립 불가·잠김을 숨기지 않는다**:
  - `impossible`: 막대 4개를 고정 링크 위에 펼쳐 놓되 **닿지 않는 틈**이 보이게 그린다(a와 c를 서로를 향해 뻗고 b를 a 끝에 이어, 모자라는 길이를 점선과 숫자로). 재생·드래그는 꺼진다. "가장 긴 링크가 나머지 셋을 합친 것보다 길어서(또는 같아서) 이을 수 없어요".
  - 한 바퀴 돌지 못하는 입력: 구동 링크가 갈 수 있는 각도 범위를 작업판에 부채꼴로, 못 가는 쪽은 흐린 빗금으로. 재생은 범위 안 왕복. 끝에 닿으면 그 자세에서 멈춘 것이 보이고(커플러와 따라 움직이는 링크가 한 줄) "여기서 더는 못 가요(사점)" 표시. 드래그로 범위를 넘기려 하면 **끝에서 멈춘다**.
- 숫자판: 구동 링크 각 / 따라 움직이는 링크 각 / 전달각 μ와 색 띠(90°에 가까우면 초록, 40° 미만·140° 초과면 주의 — "설계에서 흔히 쓰는 기준"이라고만 쓴다) / 구동 링크가 갈 수 있는 범위 / 따라 움직이는 링크의 흔들리는 범위.
- 자취: `P`(커플러 곡선). "커플러 점을 옮기면 곡선 모양이 완전히 달라져요 — 이 곡선을 골라 쓰는 것이 링크 설계예요".
- 검산값(`grashof` / `inputRange`): `3·9·7·10` 크랭크-로커, 한 바퀴 / `5·6·7·3` 이중 크랭크, 한 바퀴 / `7·3·6·8` 이중 로커(만족), 21.8°~73.4° / `3·8·3·8` 경계, 한 바퀴 / `5·4·6·10` 불만족, −75.5°~+75.5° / `2·3·3·10` 조립 불가(null) / 참고 `7·9·3·10` rocker-crank, 36.2°~88.0°.

### 7-2. 모양

- **작업판**: 약 9 × 5.6(three 단위) 크기의 세워 놓은 판 + 뒤 받침·바닥 받침(떠 있지 않게). 밝은 무광 판(`plastic` 또는 `paint`), 옅은 격자 눈금(1 cm 간격을 배율에 맞춰). 다크 테마에서도 막대와 대비가 나야 한다.
- **링크(막대)**: 양 끝이 둥근 납작한 막대(스타디움 모양 Extrude + 모따기), 핀 구멍. 폭·두께·핀 크기는 기구 배율과 무관하게 **화면에서 일정**(폭 약 0.22, 두께 약 0.05). `via` 조인트에는 중간 구멍. `slot:true`는 길게 홈이 파인 막대.
- **층**: `layer`마다 z를 약 0.09씩 띄운다. 엇갈리는 막대가 서로 뚫고 지나가지 않게(체비쇼프의 X자, 얀센, 팬터그래프). 핀은 이어진 층을 모두 관통하는 길이.
- **핀 이음**: `chrome` 축 + `brass` 머리. **고정 받침**: 판에 볼트로 붙은 `castIron` 브래킷 + 아래에 빗금 친 받침 기호(고정 링크임을 한눈에).
- **삼각 링크(plates)**: 모서리가 둥근 삼각 판(가운데를 덜어 낸 틀 모양이면 더 좋다).
- **레일·슬라이더**: `piston`=실린더 단면(양쪽 벽) + 피스톤, `ram`=안내 레일 + 램(끝에 깎는 날 모양), `block`=짧은 안내 홈 + 밀대.
- **장식(decor)**: `wheel` 기관차 바퀴(스포크, 크랭크 핀 자리), `blade` 와이퍼 고무날, `tire` 위에서 본 타이어, `slotBlock` 홈 속 블록, `floor` 바닥 선(얀센), `jawPad` 집게 끝 고무.
- **색(역할 표시 — 절제해서)**: 구동 링크 = `paint(CATEGORY_COLORS.power)`, 따라 움직이는 링크 = `paint(CATEGORY_COLORS.shaft)`, 커플러·그 밖의 링크 = `aluminum()`, 고정 링크·받침 = `darkSteel()`/`castIron()`, 자취와 추적점 = `glow(CATEGORY_COLORS.joining)`. 색이 들어가는 막대는 기구당 2종류까지. 색만으로 구분하지 않도록 화면 범례(C)와 받침 기호·손잡이 모양을 함께 쓴다.
- **손잡이**: `handle` 조인트에 잡기 쉬운 둥근 손잡이(`rubber`/`plastic`) + 은은히 맥동하는 고리(`userData.noAO = true`) — "여기를 끌어요".
- **자취(`trace.ts`)**: 추적점이 지나간 길을 굵기가 보이는 선으로(`three/examples/jsm/lines`의 `Line2` 또는 얇은 리본. 1px `Line` 금지). 점이 2,000개를 넘으면 오래된 것부터 버린다. `setFullPath`는 같은 곡선을 흐리게(불투명도 약 0.25). 팬터그래프는 P·Q 두 자취.
- 재질은 전부 `materials.ts`. 같은 재질은 변수에 담아 재사용. `castShadow`/`receiveShadow`. `dispose()`에서 지오메트리·재질 정리(`disposeObject` 참고). 기구를 20번 바꿔도 `renderer.info.memory.geometries`가 계속 늘지 않을 것.
- 직접 만들기에서 슬라이더를 끄는 동안 매 프레임 `load`가 불려도 끊기지 않게(막대 4개만 다시 만들거나 길이만 갱신).
- 좌표: 기구 좌표 (x, y) → 월드 (x, y)·판 앞면. 판 중심은 y ≈ 3.0 근처, 전체가 반경 5 안.
- `view(false, aspect)`: 정면에서 판이 가득 차게(세로 화면에서는 더 뒤로). `view(true, …)`: 오른쪽 위 약 30° 기울인 시점.

### 7-3. B의 확인 방법

확인: 관통·z-fighting 없음, 떠 있는 부품 없음, 핀이 막대 구멍 한가운데, 막대 길이가 자세마다 같음(눈으로도 늘어나 보이지 않음), 손잡이·받침 기호가 읽힘.

## 8. 17-C 화면·통합

### 8-1. 구조
- `Linkage.ts`: `AppMode`. `enter`에서 모델·패널 생성, 리스너 등록, `exit`에서 **전부** 정리(DOM, `sceneMgr.remove`, `model.dispose()`, 리스너, `controls` 상태 복원, `camera.clearViewOffset()`, `window.__lk` 삭제). enter/exit 20회 반복에 누수 없음.
- 매 프레임: 재생 중이면 입력값 진행 → `advance` → `model.setPose` → 0.1초마다 숫자판 갱신(`readouts`). 회전 입력은 일정한 각속도, 왕복 입력(swing·slide)은 사인 꼴(끝에서 부드럽게), 팬터그래프는 도형 둘레를 일정한 빠르기로.
- 좌상단 220×64px(홈 버튼·제목)은 비운다. 패널 뒤에 기구가 가리지 않게 `setViewOffset`으로 3D 중심을 옮긴다(`HandPump.ts` 방식).
- `icons.ts`: 목록용 작은 SVG 그림을 **`MechanismDef`와 `solve(q0)` 자세에서 자동으로** 그린다(막대=선, 핀=원, 받침=삼각형). 손으로 그린 그림을 따로 두지 않는다.
- `graph.ts`: `series()`로 받은 값을 SVG 꺾은선으로(가로=입력, 세로=출력, 현재 위치 점, 눈금 3~4개, 단위 표기). 한 번 그려 두고 현재 점만 움직인다.

### 8-2. 화면 구성 (넓은 화면)
- **왼쪽 패널(폭 약 320, top 76px)** — 기구 목록: 11개 카드(작은 그림 + 이름 + `oneLine`), 현재 것 강조, 키보드로 이동 가능(`role="listbox"` 또는 버튼 목록). 맨 아래가 `직접 만들기`.
- **오른쪽 패널(폭 약 312)** — 위에서부터: 기구 이름, `how`(2~3문장), **숫자판**(label / value / 작은 글씨 basis), **그래프**, **`어디에 쓰일까?` 카드**(`uses` 목록 + `watch` 한 줄), 역할 범례(구동 링크·따라 움직이는 링크·커플러·고정 링크 — 손을 올리거나 누르면 `setRoleHighlight`). 직접 만들기에서는 이 자리에 길이 슬라이더·프리셋·그라스호프 식·판정 배지.
- **아래 가운데 조작 막대**: `재생/멈춤`, `방향 바꾸기`, **빠르기** 슬라이더(분당 2~30회, 기본 10. 왕복 입력은 분당 왕복 횟수), **입력 스크러버**(회전 0~360° / 왕복은 그 범위 / 팬터그래프는 도형 선택 3개 + 진행도), 토글 `자취`(기본 켬)·`전체 경로`·`이름표`·`3D로 보기`, `자취 지우기`, `처음으로`.
- **손으로 끌기**: 캔버스에서 손잡이 조인트 근처(화면 거리 약 36px 이내)를 누르면 드래그 시작 — 재생을 멈추고, `sceneMgr.controls.enabled = false`, `model.boardPoint` → `inputFromPoint` → `advance`. 손을 떼면 controls 복원. 커서는 손잡이 위에서 `grab`, 끄는 중 `grabbing`. 터치에서도 동작(`pointer` 이벤트, `touch-action: none`은 캔버스 드래그 중에만).
  정면 보기에서는 카메라 회전을 끄고(확대·이동만), `3D로 보기`를 켜면 회전을 켠다. exit에서 원래대로.
- **키보드**: Space 재생/멈춤, ←/→ 입력 1°(Shift 10°, 슬라이드는 0.02/0.2 cm), R 방향, T 자취, [ / ] 이전/다음 기구. 입력 요소에 포커스가 있을 때는 가로채지 않는다.
- `topView` 기구(조향)는 3D 위에 "위에서 본 그림이에요" 표시.
- 기구를 바꾸면: 자취 지우기, 입력을 q0로, 카메라를 `model.view()`로, 재생 상태 유지.
- 조립이 막힌 순간(`pose.ok === false`)에는 숫자판 위에 경고 줄(`var(--warn)`)과 `aria-live="polite"` 알림. 토스트를 매 프레임 띄우지 않는다.

### 8-3. 좁은 화면 (폭 820px 미만)
- 3D는 위쪽, 아래는 시트. 시트 맨 위에 조작 막대(재생·방향·스크러버 한 줄, 44px 이상), 그 아래 탭 3개 `기구`(가로로 넘기는 칩 목록) / `숫자`(숫자판+그래프) / `쓰임새`. 직접 만들기에서는 `숫자` 탭 자리에 슬라이더와 판정.

### 8-4. 스타일 (`lab-link.css`)
- 접두어 `lk-`만. 색·간격·그림자는 `tokens.css` 변수만(밝음/다크 자동). 패널: `background: var(--panel); backdrop-filter: blur(14px); border: 1px solid var(--line); border-radius: var(--radius-l); box-shadow: var(--shadow-1)`.
- 버튼·칩·슬라이더 손잡이 터치 영역 44px 이상, `:focus-visible`, 숫자 `font-variant-numeric: tabular-nums`, `word-break: keep-all`. 이모지 금지(아이콘은 인라인 SVG 또는 글자).
- 역할 색은 `var(--cat-power)`, `var(--cat-shaft)`, `var(--cat-joining)`을 범례 점·그래프 선에만. 판정 배지: 만족 계열 `var(--ok)`, 조립 불가·사점 `var(--warn)`.
- `prefers-reduced-motion`이면 손잡이 맥동·패널 전환을 끈다(기구의 움직임 자체는 학습 내용이므로 유지).

### 8-5. 캡처·검사를 위한 진입 옵션 (C가 구현)
`preview.html`의 `&t=`는 모드에는 듣지 않으므로, `Linkage.enter`가 `location.search`를 읽는다(실제 앱의 해시 경로에서는 값이 없어 기본값으로 동작).

| 쿼리 | 뜻 |
|---|---|
| `lk=<id>` | 처음 고를 기구(기본 `crank-rocker`) |
| `lkq=<값>` | 입력값 — 각도(°) / 슬라이드(cm) / 팬터그래프는 `도형번호:진행도`(예 `0:0.5`). 주면 **멈춘 상태**로 시작. 그 값까지 q0에서 `advance`로 따라가 자취도 그 구간만큼 그려 둔다 |

| `lkdim=a,b,c,d[,u,v]` | 직접 만들기 치수(`lk=custom`과 함께) |
| `lktilt=1` | 3D로 보기 |
| `lkfull=1` / `lklabel=1` / `lktrace=0` | 전체 경로 / 이름표 / 자취 끔 |
| `lktab=uses|nums|list` | 좁은 화면에서 처음 열 탭 |

`window.__lk = { state(): { id, q, ok, failAt, readouts, grashof? }, selfLeak(): number /* geometries 수 */ }` — 스크립트 검사용, `exit`에서 삭제.
