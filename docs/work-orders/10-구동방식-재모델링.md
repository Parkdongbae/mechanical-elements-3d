# 작업 지시서 10 — 자동차 구동방식 5종 재모델링

먼저 `00-개요.md`(공통 규칙·재질·품질 기준·검증 방법), `HANDOFF.md` 6·7·10장(구동방식 기계의 사용자 지정 동작)을 읽는다.

## 배경
사용자 평가: "자동차 구동방식도 모델링이 너무 구리다. 실제와 비슷하게 업그레이드해 달라."
현재 5종(FF·FR·AWD·싱글 모터·듀얼 모터)은 OpenSCAD STL(상자·원기둥 수준)을 불러 쓴다. v2에서 재질만 바꿨다.
이번에는 **STL 형상을 버리고 절차 모델로 교체**한다(사용자가 형상 변경을 직접 요청함).

## 반드시 유지 (미션 로직·사용자 지정 동작)
- 클래스명, `id`, `stepCount`, 단계 순서와 각 단계가 뜻하는 부품(`src/data/machines.ts`), 정답 부품이 날아와 설치되는 흐름, `reset()`, 진행도 복원.
- 인트로 등장 **순서와 타이밍**(예: FR은 엔진 → 변속기 → 차동기어 → 차축 하우징 → 바퀴 4, 반축은 정답 설치 후).
- 완료 시 **어느 부품이 어느 방향으로 도는지**(회전 부호는 사용자 지정 — diff에서 부호를 바꾸지 말 것), 어느 바퀴가 구동/정지인지.
- 부품의 **조립 위치·축선**: 새 모델은 기존 STL과 같은 자리(같은 축선·같은 중심·비슷한 외곽 크기)에 놓여야 슬롯·비행 목표·회전 피벗·라벨 좌표가 그대로 맞는다.
  권장 방법 — 기존 STL의 바운딩 박스(중심·크기·축 방향)를 기준으로 절차 지오메트리를 만들어 **같은 좌표계의 BufferGeometry**로 돌려주고, 기계 파일에서는 지오메트리 출처만 바꾼다.
  STL 파일은 치수 참고용으로만 읽거나(로드 후 bbox만 사용), 치수를 상수로 옮겨 적고 로드 자체를 없애도 된다(후자 권장 — 로딩 지연 제거. 단 비동기 로딩에 의존하던 인트로/복원 로직이 깨지지 않게).
- 라벨(이름표)·지시선·'앞 FRONT / 뒤 REAR' 표시, 바퀴 회전 마커의 의미(회전이 보여야 한다 — 새 휠은 스포크가 있어 회전이 보이므로 마커는 작게 줄이거나 타이어 옆면 표시로 대체 가능).
- `src/machines/stlShared.ts`의 라벨 헬퍼는 계속 사용.

## 목표 모습
"교과서 삽화의 구동계 투시도"처럼 — 차체 윤곽 안에 동력 전달 부품이 실물처럼 보인다.

공통
- **바퀴**: 타이어(트레드 홈·옆면 굴곡) + 알로이 휠(5~10 스포크) + 브레이크 디스크. 회전이 눈에 보일 것.
- **차체**: 바닥 프레임(사다리형 프레임 또는 플로어 팬) + 반투명 차체 셸(`ghost`, 세단/해치백 실루엣 — 보닛·지붕·트렁크가 읽히는 정도)로 "자동차"임이 한눈에 보이게.
  셸은 부품을 가리지 않게 불투명도 낮게, `castShadow` 끔, 클릭/레이캐스트 방해 금지. 인트로에서 맨 먼저 또는 맨 나중에 자연스럽게 등장.
- **축류**: 프로펠러 샤프트는 양끝 유니버설 조인트(요크·십자축), 구동축(반축)은 등속 조인트 + 주름 고무 부트. 회전 표시가 보이게(조인트 요크, 축의 표시선).
- **차축(비구동)**: 토션빔/빔 액슬 형태, 허브에 연결.

내연기관(FF·FR·AWD)
- **엔진**: 직렬 4기통 — 실린더 블록, 헤드 커버(점화 코일 4개), 흡기 매니폴드, 배기 매니폴드, 오일팬, 풀리와 구동 벨트, 오일 필터. 가로/세로 배치는 기존 방향 유지.
- **변속기 / 트랜스액슬**: 벨 하우징(원뿔대) + 기어 케이스(리브) + 출력 플랜지. FF 트랜스액슬은 디퍼렌셜이 붙은 형태.
- **디퍼렌셜(차동기어)**: 호박형 하우징 + 커버 볼트, 차축 하우징(반투명 유지)과 일체로 읽히게. AWD의 센터 디퍼렌셜/트랜스퍼 케이스.

전기차(싱글·듀얼 모터)
- **구동 모터 유닛**: 원통형 모터(냉각 리브) + 감속기 케이스 + 인버터(상자, 주황색 고전압 케이블).
- **배터리 팩**: 바닥에 깔린 납작한 팩 — 셀 모듈 구획이 보이는 윗면, 테두리 프레임, 주황 케이블. 색 포인트 절제.

- 두 담당 모두: 다른 파일 수정 금지, git 명령 금지, dev 서버 재시작 금지, Claude_Browser 도구 금지. 지금 다른 에이전트 4개가 다른 기계 파일을 작업 중이다.

## 검증
- 작업 전 캡처: `node scripts/shot.mjs "preview.html?machine=drivetrain-fr&steps=all&t=3" shots/10-before-fr.png 9000` 등(STL 로딩·인트로가 있으니 대기 길게).
- 작업 후: 기계별 `steps=0`(인트로 끝난 뒤), 단계별, `steps=all&t=1` / `t=1.6`(회전 확인), 2개 이상 각도(`&cam=`), 다크 테마, `&labels=0` 1장. PNG를 직접 열어 확인.
  - 자동차로 보이는가? 엔진·변속기·디퍼렌셜·모터·배터리가 각각 무엇인지 알아볼 수 있는가?
  - 슬롯 링과 라벨이 새 모델의 올바른 자리에 있는가? 정답 부품이 제자리에 들어가는가?
  - 회전하는 부품/정지한 바퀴가 지시대로인가?
- 실제 앱 흐름: `node scripts/ui-flow.mjs drivetrain-fr light` (트레이 → 정답 → 완료 자동 진행, `shots/flow-*.png` 생성)로 5종 모두 끝까지 통과하는지 확인.
- `npx tsc --noEmit` — 자기 파일 에러 0. 삼각형 수: 기계 1개 40만 이하.
- 보고서에 기계별 권장 카메라 `view` 포함. 파일명 접두어 `shots/10-`.
