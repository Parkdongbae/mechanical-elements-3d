# 작업 지시서 21 — 「507 기계 운동」 유튜브 쇼츠 제작 파이프라인

근거: `docs/shorts/PRD-507-shorts.md`. 작성 Opus(Fable 사용 한도 중). 실제 제작은 사용자 승인 뒤.
담당: 지휘 Opus(이 세션), 구현 Sonnet/Opus 서브에이전트, 간단 검사 Haiku. GLM 은 쓰지 않는다.

## 0. 결과물과 폴더
- `scripts/shorts/` — 파이프라인 스크립트(커밋한다).
- `shorts/` — 산출물(커밋하지 않는다, .gitignore 추가): `shorts/<lang>/NNN.mp4`, `shorts/<lang>/NNN.json`(업로드 메타데이터), 중간 파일 `shorts/_work/`.
- `assets/shorts/` — 인트로 이미지(Canva), 배경음악, 효과음, 구독·좋아요 그림(커밋 여부는 음악 약관 확인 후).

## 1단계 — 도구 설치·확인(Opus, 30분)
1. ffmpeg: `winget install Gyan.FFmpeg` 또는 npm `ffmpeg-static`(가입 불필요). `ffmpeg -version` 확인.
2. 더빙: 사용자 결정(Q1)에 따라 `pip install edge-tts` 또는 Piper 내려받기. 한 문장씩 한·영 샘플 wav 를 만들어 사용자에게 들려준다.
3. 글꼴: 한글 Pretendard 또는 Noto Sans KR, 영어 Inter(무료, OFL). `assets/shorts/fonts/`.

## 2단계 — 녹화기(Opus, 2~3시간)
`scripts/shorts/record.mjs <번호> <lang>`
- Playwright 로 `preview.html?mm=<n>` 를 1080×1920(세로) 창으로 연다. dev 서버 5274(HMR 꺼짐)를 쓴다.
- 언어·이름표·화살표: 미리보기에 쿼리를 더한다(`&lang=en|ko&labels=1&arrows=0`). `src/dev/preview.ts` 에 lang·arrows 처리를 추가해 Gallery 와 같은 함수(`retextTags`, `setArrowsVisible`, 지시선 `TagLeaders`)를 쓴다.
- 프레임 단위 녹화: `window.__mm.seek(t)`·`cam(...)`·`render()` 로 30fps 의 각 프레임을 정확히 만들고 `page.screenshot` 대신 `canvas.toDataURL` 또는 CDP `Page.captureScreenshot` 로 PNG 를 `shorts/_work/<lang>/NNN/f00000.png` 에 저장(실시간 녹화가 아니라 결정적 렌더 → 끊김 없음).
- 카메라 경로(PRD §4)를 `scripts/shorts/camera.mjs` 에서 만든다:
  - 시작 = 모델 `view`(판화 구도). 궤도: 목표점 둘레로 정면 → 오른쪽 위 45°, 거리 1.0 → 0.8배.
  - 클로즈업 대상: `userData.mm` 에서 맞닿는 자리 고르기 — 물린 기어 쌍의 접점, 줄·벨트 wraps 의 가운데, outline 을 가진 부품끼리 가장 가까운 점, 없으면 이름표가 가장 많이 몰린 곳. 대상 거리 0.35배, 재생 0.5배.
  - 마지막 1초 전체 보기.
  - 번호마다 결과를 `shorts/_work/cam/NNN.json` 으로 남겨 사람이 손볼 수 있게.
- 판화 겹치기: 첫 2초에 판화(`public/mm507/fig/NNN.png`)를 같은 구도에 맞춰 화면 위에 놓고 투명도 1 → 0.

## 3단계 — 대본·더빙·자막(Sonnet 대본, Opus 합성기, 2시간 + 번호당 수 초)
1. `scripts/shorts/script.mjs` — catalog 의 easy/easyEn 을 PRD §5 길이로 줄인 대본을 `shorts/scripts/<lang>.json` 에 만든다(Sonnet 에게 묶음 50개씩 맡기고, 스크립트가 길이·금지어 검사).
2. `scripts/shorts/tts.mjs` — 대본 → wav + 단어 시간(edge-tts 는 WordBoundary 제공). 길이가 10.5초를 넘으면 말 빠르기 +10%, 그래도 넘으면 대본을 다시 줄이게 표시.
3. 자막: 단어 시간으로 2~3단어씩 묶은 ASS 자막(아래 1/4 지점, 굵은 글꼴, 지금 읽는 단어 강조).

## 4단계 — 인트로·아웃트로 그림(Canva + Opus, 1시간)
1. Canva(이 세션에 연결된 Canva 도구 `generate-design`/`create-design`)로 1080×1920 인트로 2장(PRD §8). 사용자에게 보여 주고 고른 것을 PNG 로 `assets/shorts/intro-ko.png`, `intro-en.png` 로 내보낸다.
2. 아웃트로: 앱 화면 캡처 + "직접 돌려 보세요 / Try it yourself" + 주소 + 구독·좋아요 아이콘(직접 그린 SVG → PNG, 유튜브 로고는 쓰지 않는다 — 상표).

## 5단계 — 합성(Opus, 2시간)
`scripts/shorts/compose.mjs <번호> <lang>` — ffmpeg 한 번 실행으로:
- [0~1.5초] 인트로 PNG(줌 1.0→1.06) + 번호 글자 얹기 → [1.5~11.5] 녹화 프레임 → [11.5~14.5] 아웃트로.
- 오디오: 배경음악(곡 목록에서 번호 % 곡 수) -18 LUFS, 더빙 -14 LUFS, 효과음, 끝 1.5초 페이드아웃.
- 자막 입히기(ASS), H.264 high, yuv420p, 30fps, AAC 192k, 길이 ≤ 14.5초 검사.
- 메타데이터 JSON(PRD §9: 제목·설명·태그·링크).

## 6단계 — 검수와 묶음 제작(Haiku 검사, Opus 표본)
- `scripts/shorts/check.mjs` — 길이, 해상도, 소리 크기, 무음 구간, 자막이 화면 밖으로 나가지 않는지, 마지막 프레임 아웃트로 여부.
- 첫 10편(한·영 각 5)을 사용자에게 보여 주고 승인받는다. 승인 뒤 1~160번 전체를 묶음(병렬 4개)으로 만든다. 번호당 녹화 약 1분, 합성 약 20초 예상 → 320편 약 7시간.

## 7단계 — 업로드(사용자 결정 Q3)
- 직접 업로드: 파일과 메타데이터 JSON 을 넘긴다.
- 자동 업로드: YouTube Data API v3 — 사용자가 Google Cloud 프로젝트·OAuth 클라이언트를 만들고 처음 한 번 로그인 동의. 하루 할당량(기본 10,000 단위, 업로드 1회 1,600 단위 → 하루 6편) 때문에 예약 업로드로 나눈다.

## 사용자 결정(2026-11-25)
- Q1 더빙: **edge-tts**. 목소리는 1단계 샘플(한·영 남녀)을 들려주고 고른다.
- Q2 배경음악: **유튜브 오디오 보관함** — 사용자가 YouTube Studio 에서 곡 3~5개를 내려받아 `assets/shorts/music/` 에 넣어 준다.
- Q3 업로드: **YouTube Data API 자동 업로드** — 사용자가 Google Cloud 프로젝트 생성·YouTube Data API v3 사용 설정·OAuth 클라이언트(데스크톱 앱) 만들기·처음 한 번 로그인 동의. 하루 할당량 때문에 예약 업로드(하루 약 6편)로 나눈다. 클라이언트 비밀 파일은 저장소 밖(또는 .gitignore)에 둔다.
- Q4 채널: **한 채널** — 제목 앞에 [한]/[EN] 을 붙이고, 재생목록을 언어별로 나눈다.
