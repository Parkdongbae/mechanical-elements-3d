# 069 한 톱니 정지 바퀴
원문: 한 개의 톱니가 있는 작은 바퀴 B 가 구동 쪽이다. 바퀴 A 의 톱니 사이로 들어가는 (B 의) 둘레는, 작은 바퀴의 톱니가 작용하지 않는 동안 잠금 또는 정지구가 된다.

## ★ 판화 읽기
판화는 그림 하나(정면).
1. 바퀴는 몇 개이고 크기 차례는? → 2개. 큰 톱니바퀴 A(왼쪽 아래)와 작은 바퀴 B(A 의 오른쪽 위, A 중심에서 위로 약 27°). B 의 둥근 판 반지름은 A 이끝 반지름의 약 0.27배, 중심 거리는 약 1.23배.
2. 줄·벨트는? → 없음.
3. 교차하는 가닥은? → 없음.
4. 고정점은? → 판화에는 받침이 없다(두 축의 단면만).
5. 추·손잡이·크랭크는? → 없음. 구동은 B(원문).
6. 이는 어디에 났고 무엇이 물리는가? → A 의 바깥 둘레에 뾰족한 톱니 약 31개(판화 윤곽에서 각 간격 11.6° 로 셈). B 는 둥근 판 + 오른쪽 위로 뻗은 손가락(톱니) **하나**, 손가락 양옆의 판 둘레는 도려 냈다(위쪽 턱, 아래쪽 갈고리 모양 끝). B 의 둥근 둘레 왼쪽이 A 의 두 이 사이로 조금(이 높이의 약 1/4) 들어가 있다. 판화의 순간은 **잠긴 때**: 손가락이 A 반대쪽을 본다.
7. 한 줄에 놓인 것은? → 없음(B 는 A 의 오른쪽 위 비스듬히).
8. 글자가 가리키는 부품은? → A = 큰 톱니바퀴, B = 한 톱니 구동 바퀴. 화살표(B 위, 왼쪽을 향함) = 반시계.
9. 판화와 원문이 다르거나 판화대로 돌 수 없는 곳은? → 기구는 같다. **치수만 판화대로는 닫히지 않는다**: 판화의 손가락(끝 반지름이 판 반지름의 1.6배)은 A 의 이뿌리보다 깊이 들어가고, 판화 크기의 판(0.3)·잇수 30 으로 풀면 한 바퀴에 이 두 개(23.8°)가 넘어간다(`s069.mjs` 로 확인). 한 바퀴에 이 하나가 되게 B 를 줄였다 — 아래 해석. 기구가 달라지는 것은 아니므로 질문 거리 아님.
- 그 밖의 선: 축 둘레 두 겹 원 = 허브 고리.

## 구동
B(반시계) theta += OMEGA(1.6)·speed·dt. A 는 B 가 한 바퀴 돌 때 이 하나만큼(시계)만 돌고 나머지 시간은 B 의 둘레에 잠겨 선다.

## 해석(결정 사항)
- A 의 이 수는 판화(약 31)와 달리 **28**. 이유: 손가락이 이를 미는 각(실측 12.97°)이 이 하나의 각(360/28 = 12.857°)과 거의 같아야 한 바퀴마다 정확히 이 하나가 닫힌다(34 이면 피치 10.6° 라 손가락이 두 이를 밀거나 못 민다). 시각은 판화와 거의 같다(톱니 빽빽한 큰 바퀴).
- **B 는 판화보다 작다**(판 반지름 0.17 = A 이끝의 0.14배, 판화는 0.27배; 손가락은 판 밖으로 0.03 만 나옴, 판화는 판 반지름의 0.6배). 판화 크기로는 한 바퀴에 이 두 개가 넘어가서(위 9번) 줄였다. 눈 검증 E1 에서 "B 가 판화보다 작다"는 알고 넘어간다.
- B 는 판화처럼 거의 둥근 판 + 손가락 하나. 판의 손가락 둘레 ±50° 만 도려 내(이 끝이 판 속으로 지나가도록), 나머지 둘레 260° 가 A 의 이 사이에 앉아 A 를 잠근다.
- 이 모양: 대칭 뾰족 삼각형(판화의 날카로운 톱니).

## 부품과 치수 (키트 추가 `k069.ts`)
`pointedWheel`, `oneToothDriver`(키트 추가), `shaftZ`, `rotArrow`, `tag`, `displayStand`(판화에 없음 — 공통 받침). 모든 값은 `K69` 상수. 부품 name: A `wheelA`, B `driverB`.
- A: `pointedWheel(28, 1.2, 1.06, { width: 0.1, holes: 6 })` 이끝 반지름 1.2, 이뿌리 1.06(이 높이 0.14), 이 i 는 로컬 각 i·12.857° 에 이끝. 중심 (−0.3, 1.5), z = 0.12. 구멍 6개, 표시점 1개.
- B: `oneToothDriver(0.17, 0.20, 0.04, 50, { width: 0.1 })` 판 반지름 0.17, 손가락 길이 0.20(끝 폭 0.04), 손가락 방향 = 로컬 +X, 중심 = A 중심 + 1.34·(cos 29.5°, sin 29.5°) = (0.8665, 2.1595), z = 0.12. 청동색(구동), 손가락에 표시점.
- 축: `shaftZ(−0.3, 1.5, 0.3)`, `shaftZ(0.8665, 2.1595, 0.3)`.
- 전시 영역 안: x −1.5 ~ 1.1, y 0.3 ~ 2.7, z −0.30 ~ 0.35.

## 동작 (theta = 누적 각 θ)
- 손가락 각 rel(도) = −150 + θ(도) 를 (−180, 180] 로 접는다(q = 접은 횟수). rel 은 손가락이 A 중심을 향할 때 0. B 회전각: B.rotation.z = (A 쪽 방향각 29.5° + 180°) + rel = 209.5° + rel(도). 시작 rel = −150°(판화와 거의 같은 자세: 손가락이 A 반대 쪽, 약 30° 앞서 있음).
- A 의 시계방향 누적 회전 a(도) = `oneToothAngle(−150 + θ(도))` = 2.6357 + q·12.857 + onePushDeg(rel). A.rotation.z = −a(라디안).
- 주기 시간표(한 바퀴 = B 360°, 2π/1.6 = 3.93 s): rel −180 ~ −48 (132°, 36%) 정지(B 둘레가 잠금), rel −48 ~ +36 (84°, 23%) A 가 한 이(12.857°) 전진(표 `onePushDeg` 1° 간격, 처음 급히 밀리다 천천히 끝남), rel +36 ~ +180 (144°, 41%) 정지. 속도비 B : A = 28 : 1(B 28 바퀴에 A 1 바퀴).
- 이 표는 `shots/_verify/s069.mjs`(N=28 D=1.34 RB=0.17 RFIN=0.20 WC=50 FW=0.04)의 충돌 시뮬레이션: A 가 닿는 즉시 밀려난 각을 1° 씩 기록하고 한 이 각으로 정규화(×0.9912).
- 물림(맞물림 아님 — 미는 접촉): 접점이 손가락 옆면과 이 옆면. 이는 `meshAngle` 이 아니라 위 표로 맞춘다.

## 표시
- rotArrow: B 반시계(반지름 0.3, B 중심 위치 z = 0.17), A 시계(반지름 0.55, 중심 z = 0.17).
- tag(3개 이상): 'B(구동 · 이 하나)', 'A(톱니 28 · 한 칸씩)', 'B 의 둥근 면 = 잠금', '도려 낸 곳(이가 지나감)'.
- notes: '한 톱니 B : 톱니 28 A = 28 : 1', '이번 바퀴 A 전진 n / 12.86°', '상태: 잠금 중 / 미는 중'(rel −48 ~ +36 이면 '미는 중'), A 회전수.

## 확인
- t=1 (θ = 91.7°, rel −58°): 손가락이 아직 이에 닿기 전, A 정지(회전 2.6°). B 의 둥근 면이 이 사이에 앉아 있다.
- t=1.6 (θ = 146.7°, rel −3°): 손가락이 A 의 이 틈 한가운데에 들어가 이를 밀고 있다. A 가 시계 방향으로 약 9° 간 상태(notes '미는 중').
- 근접 `cam=0.4,2.4,1.6,0.6,2.0,0.12`(접점), 옆 `cam=3.2,2.1,0.12,0.6,2.1,0.12`: 손가락·판이 이 속으로 박히지 않음(침범 깊이 ≤ 0.002), 잠금 구간에서 판 둘레가 두 이 옆면에 닿음(틈 없음).
- 수치(검사 B7): 두 윤곽(`userData.outline`)을 rel −180 ~ 180 에서 한 이 각 전진 표대로 옮겨 점-다각형 침범 깊이를 잰다 → 최대 0.0017.
