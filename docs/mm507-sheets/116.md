# 116 크랭크 대신 쓰는 이중 랙
원문 요지: 크랭크의 대용품. 이중 랙이 달린 **틀이 곧게 왕복**하면 **피니언 축이 한 방향으로 계속 돈다**. 랙마다 피니언이 하나씩 따로 있고 **두 랙은 서로 다른 평면**에 있다. 두 피니언은 축 위에서 헐겁게 돈다. 각 피니언 바깥쪽 축에는 래칫 바퀴가 고정되어 있고, 피니언에 붙은 폴이 그 래칫에 걸린다. 틀이 한쪽으로 갈 때는 한 피니언이, 반대로 갈 때는 다른 피니언이 폴과 래칫으로 축을 **같은 방향**으로 돌리고, 그동안 나머지 피니언은 축 위에서 헛돈다.

## ★ 판화 읽기
판화는 그림 하나(정면). 4배 확대 `shots/_verify/116-fig-x4.png`, 가운데 8배 `shots/_verify/116-fig-c.png` 로 다시 읽음.
1. 바퀴는 몇 개이고 크기 차례는? → 정면에서 보이는 것은 피니언 1개(이 12개)와 그 앞의 래칫 바퀴 1개(갈고리 꼴 이 8개쯤, 지름이 피니언의 약 0.53배). 원문대로면 같은 축 위에 **피니언 2개·래칫 2개**가 앞뒤로 겹쳐 있어 정면에서는 하나로 보인다(판화의 피니언이 윗랙·아랫랙 둘 다와 물린 듯 그려진 까닭). 가운데 빗금 원 = 축의 단면(지름이 피니언의 약 0.35배).
2. 줄·벨트는? → 없음. 대신 랙 2개: 길쭉한 틀의 창 위 가장자리에 아래로 향한 이 12개쯤, 아래 가장자리에 위로 향한 이 11개쯤.
3. 교차하는 가닥은? → 없음. 겹침 순서: 래칫·폴이 피니언 앞, 축 단면이 맨 앞.
4. 고정점은? → 판화에는 없다(틀 양끝의 막대가 잘려 있을 뿐). 축은 제자리에서 돌고 틀은 좌우로만 움직여야 하므로, 모형은 축을 뒤판 보스로, 틀 양끝 막대를 뒤판에서 나온 안내 블록 두 개로 받친다(판화에 없음).
5. 추·손잡이·크랭크는? → 없음. 구동은 틀(원문: 틀의 왕복이 축의 회전을 만든다). 틀 오른쪽 끝의 목 달린 둥근 막대가 구동 쪽(피스톤 막대 따위)으로 이어지고 왼쪽 끝은 짧은 네모 막대.
6. 이는 어디에 났고 무엇이 물리는가? → 랙의 이는 틀 창의 **안쪽** 위·아래 가장자리에 났다. 피니언은 창 속 가운데에 있고 바깥 이로 물린다: 앞 피니언 ↔ 윗랙(앞 평면), 뒤 피니언 ↔ 아랫랙(뒤 평면). 폴은 피니언의 왼쪽 위(약 135° 자리)에 받침 핀이 있고 끝이 래칫의 위쪽(약 85°)에 걸린다 → 받침에서 끝으로 가는 방향이 시계 방향이므로 **이 피니언은 시계 방향으로 돌 때 래칫(축)을 민다.**
7. 한 줄에 놓인 것은? → 축 중심·피니언 중심·래칫 중심이 한 점. 틀의 가로 가운데선(양끝 막대의 중심선)이 축 중심 높이. 윗랙·아랫랙의 피치선이 축에서 같은 거리.
8. 글자가 가리키는 부품은? → 글자 없음(번호 116 뿐).
9. 판화와 원문이 다르거나 판화대로 돌 수 없는 곳은? → 기구가 달라질 만큼 다른 곳은 없다. 정해야 했던 것 세 가지(아래 "해석")는 판화·원문에서 풀리므로 사용자 확인 불필요: ① 어느 랙이 앞 평면인지 — 판화에 없음(겹쳐 그려짐) ② 원문 "두 래칫의 이가 서로 반대 방향" — 각 래칫을 제 바깥쪽에서 본 방향(거울상으로 조립)이라는 뜻으로 읽는다. 정면 한쪽에서 보면 두 래칫의 이는 **같은 방향**이어야 축이 한 방향으로 돈다(반대로 깎으면 축이 잠긴다) ③ 판화의 래칫 이가 어느 쪽으로 누웠는지는 흐려서 판화로는 알 수 없음 — 폴의 방향(6번)으로 정했다.
- 그 밖의 선: 틀의 바깥 선과 안쪽 선 두 겹 = 틀 살의 두께. 래칫 이의 굽은 선 = 갈고리 꼴 이(모형은 곧은 등으로). 폴 위의 짧은 겹선 = 폴의 두께.

## 해석(결정 사항)
- **앞 평면 = 윗랙 + 앞 피니언 + 앞 래칫(판화에서 보이는 것), 뒤 평면 = 아랫랙 + 뒤 피니언 + 뒤 래칫.** 판화의 폴 방향대로 앞 피니언이 시계 방향으로 돌 때 미는 것으로 하면, 틀이 **오른쪽**으로 갈 때 윗랙이 앞 피니언을 시계 방향으로 돌려 축을 밀고, 틀이 **왼쪽**으로 갈 때는 아랫랙이 뒤 피니언을 시계 방향으로 돌려 축을 민다 → **축은 늘 시계 방향.**
- 두 래칫·두 폴은 정면에서 보아 같은 방향(둘 다 시계 방향으로 밀림). 뒤 폴·뒤 래칫은 뒤 피니언의 뒷면 쪽에 있어 정면에서는 가려지고 비스듬히 보면 보인다.
- 한 행정에 피니언이 정확히 90°(= 래칫 2피치) 돌게 행정을 잡았다 → 헛도는 행정 동안 폴이 래칫 이를 정확히 4개 넘고, 행정이 바뀌는 순간 폴이 이 면에 딱 걸린다(헛걸음·누적 오차 없음).
- 틀 창은 판화보다 짧다(판화 창 길이 ≈ 피니언 지름의 3.3배, 모형 3.0배 — 양끝 안내 블록까지 전시 폭 ±2.2 안에 넣으려고). 랙 이 수는 9개(판화 11~12개).
- 틀의 운동은 사인 꼴 왕복(판화에 구동이 없어 정함) → 축은 한 방향으로만 돌되 속도는 틀 속도를 따라 맥동한다(원문의 "고른 회전"은 플라이휠이 있을 때의 이야기).

## 구동
틀(name `frame`)의 왕복. theta += OMEGA(1.6)·speed·dt. 위상 u = 2·(theta − 1.6) + π/2, 틀 x = −0.2356·cos u. 한 행정(u 가 π 만큼) 0.98 s, 왕복 1.96 s.

## 동작 (모두 theta 의 닫힌 식 — `state116(theta)` 가 돌려준다)
`const s = state116(theta)` → `{ x, shaft, pinF, pinR, liftF, liftR, drive, strokes }`
- 틀: `frame.position.x = s.x` (±0.2356, 행정 0.471 = 랙 3피치).
- 앞 피니언: `pinionF.rotation.z = s.pinF` (= −x/0.30, 윗랙과 물림). 뒤 피니언: `pinionR.rotation.z = s.pinR` (= +x/0.30, 아랫랙과 물림). 두 피니언은 늘 서로 반대로 돈다. x = 0, 각 0 에서 피니언의 이골이 위·아래를 향하고 두 랙의 가운데 이가 거기 든다(위상은 키트가 맞춰 둠 — 모델은 각을 더하지 않는다).
- 축·두 래칫: `shaft.rotation.z = ratchetF.rotation.z = ratchetR.rotation.z = s.shaft` (= −(틀이 움직인 총 거리)/0.30, 늘 줄어든다 = 시계 방향). 짝수 행정(틀이 오른쪽으로)은 앞 피니언과 한 몸으로, 홀수 행정(왼쪽으로)은 뒤 피니언과 한 몸으로 돈다.
- 폴: `pawlF.rotation.z = pawlBaseF + s.liftF`, `pawlR.rotation.z = pawlBaseR + s.liftR`. 미는 쪽은 들림 0(이 면에 걸림, 틈 0.0013), 헛도는 쪽은 래칫 이의 등을 타고 최대 17.3° 들렸다가 다음 이골로 떨어지기를 한 행정에 4번.
- 시각: **t = 1.0 (u = 90°, 틀이 가운데 = 판화 자세, 오른쪽으로 가는 중, 앞 피니언이 밂)**, **t = 1.3 (x = +0.193, 아직 앞 피니언이 밂)**, t = 1.6 (x = +0.221, 방향이 바뀌어 왼쪽으로 가는 중 — 뒤 피니언이 밂), t = 1.49 (오른쪽 끝).

## ★ 난도·질문
난도 **B** (부품·운동식·폴 들림이 모두 키트에 있다. 모델은 배치와 `state116` 결과 대입이지만 앞뒤 두 평면·자식 폴·따라가는 이름표가 있어 A 보다 한 단계 위).
사용자에게 물을 질문: 없음. 보류 아님. (참고로 정한 것: 윗랙이 앞 평면, 축은 시계 방향, 두 래칫은 정면에서 같은 방향, 틀은 사인 꼴 왕복.)
